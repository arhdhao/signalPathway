## 架构审查：换模拟机制的可行性与耦合面（讨论，未改代码）

arhdhao 提出「现在的机制是不是太复杂、能不能只换 nocgmp.ts、engine 要不要大改」。
读完 engine.ts / nocgmp.ts 并扫了 render.js / ui.js 的耦合面，结论如下。

### 机制本质
不是 ODE 也不是 Gillespie，是「确定性骨架 + 伯努利门控 + 双标量状态」：
每 tick（10Hz）掷一次 0–100 骰子，命中就加 `drive^hill` 加权增量，不命中为 0。
复杂度不在代码量（核心结算约 110 行），而在**参数语义不正交 + 耦合面没封干净**。

### 查出的具体债（都有行号，可日后逐个清）
- `nocgmp.ts:314` 节点级 `band` 不参与计算 → sGC 的「命中频段」滑块是假的（文件内已标 TODO）
- `engine.ts:627-630` `_ntgBoost/_ntgFactor/_ntgPeriod` —— 硝酸甘油状态硬编码在引擎里，
  违背文件开头「引擎不认识任何分子名」的自述原则；第二关再有 boostPulse 类药物会串味
- `engine.ts:898` 多条 consume 边指向同一底物时按同一快照重复扣减，可能为负（现仅 r6 一条，未暴露）
- `engine.ts:859` produce 直接 `nextCount += made`，无 room 上限，多 produce 边会超产
- **渲染/UI 层 6 处硬编码分子名（最关键）**：
  `render.js:247 sim.node('NO')`、`:249 m.count/55`、`:248 sim._pulseClock`、`:528 sim._readValue`
  `ui.js:203/220 level.redline.cGMP`、`ui.js:360-362 node('cGMP'/'PKG'/'PDE5')`
  → 「换关卡不用动 UI」目前**不成立**。修法：LevelConfig 加 `uiRefs` 配置块，UI 改读配置。

### 三档换法的代价（已给 arhdhao 图示）
- **A 换关卡（同机制换通路）**：engine 0 行；但需先清上面 6 处硬编码，否则 UI 炸
- **B 换数值内核（同数据模型换算法）**：engine 改 3 个方法（Molecule.drive / _resolveReaction /
  Molecule.onTick，约 120 行）；关卡只动 ④ KINETICS；**只要保留 count/activation/status/flash/
  lastGain 字段名，渲染层零改动**
- **C 换建模范式（布尔/ODE/Gillespie）**：LevelConfig schema 要重设计（缺 rate、化学计量系数，
  count 是浮点不是整数），engine 改 30–50%；但六层里的 BIOLOGY/VIEW/GAME/COPY 四层能完整复用

### 我的建议（已提出，等他决策）
走 **B 的确定性化**：伯努利换成连续 Hill（`vmax·drive^n/(K^n+drive^n)`），保留边列表模型。
理由：现在的二值噪声两头不靠（既非真实分子噪声也非干净 ODE），最难配平也最难向学生解释；
确定性化后 K/n/vmax 三者正交，可手调；想留「活物感」可在显示层叠 ±3% 观测噪声而非让噪声
参与动力学。代价是失去掷骰子的桌游味。

### 待他回答的两个问题
1. 想换的方向：更真（ODE/Gillespie）/ 更简单（布尔）/ 只是旋钮太多想瘦身？
2. 痛点是「配平难」还是「表达力不够」？若只是配平难，参数正交化（band×hill×power → K+n+vmax）
   代价远小于换机制。

提议（未执行）：做同关卡双内核原型跑 balance 比结局分布，用数据决策。

## 第二轮：arhdhao 提出「池子 / 小桶 / 账本」新架构（讨论，未改代码）

他独立重新设计了一套内核，剥离所有外衣后只剩三件东西：
1. **池子（State）**：只存数字不存实体，node → number（NO=50, cGMP=2000, GTP=8000）
2. **小桶（反应规则）**：每只桶每 tick 固定 N 次（如 20 次）碰撞尝试，每次 = 对密码 + 掷骰子
3. **账本（Delta 缓冲）**：各桶只记增减，回合末一次性冲正回池子

### 我的判断：值得换，有理论依据，但有一处内部矛盾

**学术定位**：「固定 N 次尝试 + 每次伯努利」抽出的是 Binomial(N,p)；N 大 p 小时收敛到
Poisson(Np)，而 Poisson(λ=propensity×τ) 正是 **τ-leaping**（Gillespie 2001）。
→ 他的小桶 = **τ-leaping 的二项近似**，是标准方法的工程简化，不是野路子。

**三个真实收益**：
1. **噪声性质变对**：二项分布相对波动 √(p(1-p)/N)/p —— 低浓度抖、高浓度自动平稳，
   符合低拷贝数噪声特征。现在引擎每 tick 只掷一次骰子，相对波动恒定 ±100% 且与浓度无关，
   这才是难配平的根因。
2. **竞争性抑制从连续瓜分变离散抢配额**：现在是 `cap × m.count/total` 浮点瓜分；
   离散版是「N 次机会按浓度加权抽，抽到诱饵白扔一次」，更好解释且天然带随机性。
3. **参数接近正交**：attempts（通量）/ p（命中率）/ unit（单次产量）各管一件事，
   不像 band×hill×power 互相纠缠。

### ⚠️ 必须点破的内部矛盾（实施时第一个会卡住）
他「小桶」定义是两步：① 对密码 ② 掷骰子 [Min,Max] —— 这个流程命中概率**只取决于骰子
区间，与浓度无关**，则西地那非再多也不会减少 cGMP 被降解的次数，竞争抑制出不来。
但他案例里写的「PDE5 发现西地那非比 cGMP 多得多，抓到它的概率极大」是**按浓度加权选底物**，
是另一个动作，两步流程里缺了它。
→ **正确的桶内循环是三步**：① 按浓度加权抽底物 ② 对密码 ③ 掷骰子命中则记账。
少了第 ① 步，案例描述的效果不成立。（已画 20 格分配图给他：cGMP 200 / 西地那非 600
按 1:3 加权 → 5 次抓 cGMP 命中 3 次 −3，15 次抓西地那非空转；没吃药时 20 次全抓 cGMP 是 −12）

### 实施必补的四件事
1. **attempts 不能硬编码 20** —— 必须是 `round(活性酶数量 × turnover)`，否则酶多一倍反应
   不快一倍，剂量-响应丢失。turnover 配在反应上，attempts 每 tick 现算。
2. **反应要声明参与者角色**（他的 JSON 表达不了「检查 sGC 和 GTP」，因为两者作用不同）：
   `gate`（定配额、不消耗，如 sGC/PDE5）/ `substrate`（加权抽样候选、命中则消耗）
   / `product`（命中则增加）/ `decoy`（占位但 amplify=0 不消耗自身）
3. **需要 unit 参数做量级解耦** —— 若池子存分子个数，每次命中产 1 个则 200 个/秒，
   与西地那非 620、GTP 1000 量级对不上。unit 管数量级，attempts 管统计特性，两者分开才好配平。
4. **酶的激活要显式建模成第二个池子** —— 统一成单一数字后 PDE5 激活度无处放，
   需 `PDE5_active` / `PDE5_total` 两个池子，激活=搬迁数字，衰减=搬回。更物理但池子条目翻倍。

### 成本诚实评估
不是「工作量更小」，是「概念更少、配平重来」：
- 引擎核心循环反而**变短**（110 行 → 60–80 行）
- `KINETICS` 层整个重写（band/hill/power → turnover/p/unit），balance.mjs 基线全废
- 顺手清 render/ui 那 6 处硬编码
- count/activation 合并后，渲染层两处 `isCount ? ... : ...` 分支要统一

### 我的落地建议
**别直接重写 engine.ts**。新写 `engine-v2.ts` 实现同样的 Simulator 接口（tick / applyDrug /
history / metrics 输出一致），与现引擎并存，用同一批 balance.mjs 场景跑两边对比结局分布，
数据说话再切默认。万一新内核配不平还有退路。
已提议先搭最小可跑 v2 骨架（池子 + 一只降解桶 + 账本），验证西地那非案例能否跑出
−3 vs −12 的对比。**等他点头。**

## 第三轮：围绕「分子间掷骰子」的五种可选内核（讨论，未改代码）

arhdhao 问：除了上面那些，还有哪些「两个分子掷骰子决定交互」的模拟思路。

### 统一的判断框架（本轮核心贡献）
所有方案的区别不在「怎么掷骰子」，而在**随机性注入到哪一层**，一共只有三个位置：

| 方案 | ① 抽「发生几次」 | ② 抽「抽中谁」 | ③ 抽「成不成」 |
|---|---|---|---|
| 现状引擎 | 每边固定 1 次 | 不抽（from→to 写死） | 掷骰，概率=f(drive) |
| 池桶账本（他提的） | 固定 N 次 | 按浓度加权 | 掷骰，概率固定 |
| ① 随机碰撞 | **次数随机** Poisson(κ·N_A·N_B) | 由配对自带 | 掷骰 |
| ② 泊松轮盘 | **次数随机** Poisson(a_j·dt) | 不抽 | 不抽，个数即结果 |
| ③ 概率布尔 | 固定 1 次 | 不抽 | 掷骰，状态仅 0/1 |

**关键洞察：现在引擎随机性只加在第 ③ 层；池桶方案加在 ②③；真正的物理在第 ① 层。**

### 五个方案（含我的排序）

**① 随机碰撞配对（首选）** —— 每 tick 分子按 Well-mixed 假设随机两两配对，每对各掷一次骰子。
相遇次数 ∝ N_A×N_B → 质量作用定律直接涌现，三个副产品：
米氏饱和（酶有限→Vmax 自动出现）/ 竞争性抑制（诱饵稀释配对概率，2 次 → 0.7 次）/
级联放大（一个酶连续配多个底物，不需要手填 amplify 常数）。
顺带解决上轮指出的两个问题：通量不用硬编码、竞争不用单独加权抽样。
代价：分子数上千时列举开销大 → 可从超几何/多项分布直接抽「配成几对」（数学等价但不直观）；
可留「列举模式（教学关）/ 抽样模式（大数量场）」两档。

**② 倾向性泊松轮盘（次选 / τ-leaping 标准形式）** —— 每条边声明 propensity 公式，
Poisson(a_j·dt) 抽个数，个数即结果。表达力最强，碰上难以涌现的机制（别构、转录延迟、
受体脱敏）可直接手写公式。COPASI / BioNetGen 都是「简单边涌现 + 复杂边显式」的混合式。
代价：回到手写公式，涌现性弱于 ①。

**③ 活化能势垒（Metropolis / Arrhenius）** —— p = exp(−ΔE/kT)，骰子有了物理含义。
收益：酶的催化=降 Ea、抑制剂=抬 Ea、温度成真参数；西地那非不再是 `degradable:false`
这种特判开关，而是「结合能高但反应势垒无限高」。代价：每个反应多标定一个 ΔE，
且只有相对大小有意义，配平直觉要重建。

**④ 空间格子（元胞自动机）** —— 分子撒网格上只跟邻域碰，放弃 Well-mixed。
收益：能看到 NO 从内皮向平滑肌的扩散梯度（第一关真实存在、现在是抽象箭头），视觉价值大。
代价：世界观改变 + diffusion-limited + 全量重配平 + 性能。**建议不做内核，只做可视化层**：
内核照旧 Well-mixed，渲染时把池子数字撒到网格上做扩散动画。

**⑤ 概率布尔网络（极简档）** —— 节点 ON/OFF + 带概率逻辑门。没有「量」，
做不出剂量-响应与竞争抑制，但与文献通路图一一对应最易讲。
**建议做「教学模式档」**：同一关卡数据，布尔档讲拓扑逻辑、完整档做配平 —— 正好契合
他「学生 / 研究者双向受众」的定位。

### 我的排序理由（不是精度，是后续关卡的成本）
现在 `_resolveConsume` 是专门为竞争性抑制写的**特判模块**；将来加别构抑制、反馈磷酸化、
受体脱敏，每种机制都要加一个分支，**引擎随关卡数线性膨胀**。
方案 ① 把这些变成配对统计的副产品，机制涌现 → 引擎不随关卡膨胀。
这才是换内核的真正回报，比「代码更短」值钱。

### 落地提议（等他点头）
先跑方案 ① 的最小验证：用随机碰撞跑出「降解 2 次 vs 0.7 次」，
确认竞争性抑制在**不写任何特判**的情况下能涌现。这条通了再谈配平。
