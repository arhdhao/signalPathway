## 浓度动态新增 sGC / PDE5 / PKG 三条曲线

**关键结论：引擎一行没动。** `Simulator._snapshot()` 本来就遍历 `level.chart.series`
调 `_readValue()` 写 history，而 `_readValue` 原生支持 `{kind:'node', prop:'activation'}`。
所以「新增输出变量」这件事**只需在关卡的 CHART.series 加三行**，采样自动跟上。
（sGC/PDE5/PKG 的 activation 一直存在于 `sim.nodes` 里，balance.mjs 的输出表本来就在打它们，
只是没进 history 快照 —— 缺的是「记录哪些」，不是「状态存不存在」。）

**改动**
- `engine.ts`：`ChartSeries` 加可选字段 `dash?: number[]`（线型，纯绘图配置，不碰动力学）。
- `nocgmp.ts` CHART.series：新增三条 `prop:'activation'`。
  颜色避开撞色 —— 画布上 sGC=#4dd0c7（同 cGMP 曲线）、PDE5=#ff7a6b（同 Ca 曲线），
  所以另配 紫 #b39dff / 琥珀 #ffd479 / 粉 #ff9de2，各配一种 dash 作为第二重区分（色觉障碍也能分）。
- `render.js` Chart.draw()：支持 `s.dash`；图例改用 `measureText` 自适应宽度并支持换行
  （原来写死 `lx += 52`，5 条会挤）；端点标注改成先收集再按 y 排序、间隔 <11px 就推开、
  整组超界再回推，避免 5 个数字叠成一坨。
- 标题 `浓度动态` 改为 UI 里从 `chart.series` 动态拼（`浓度动态 · Ca²⁺ · cGMP · sGC(%) · PDE5(%) · PKG(%)`），
  以后增删曲线标题自动同步。

**实测数值（决定了不用双 Y 轴）**
sGC / PDE5 / PKG 的 activation 都是 0–100 量级（实测 max 54.9 / 81.7 / 74.4），
Ca 40–100，与现有 chart.max=160 同一量级 → **共用同一纵轴即可，不要开第二套轴**
（双轴最容易让人误读大小关系）。量级真差很多时才考虑归一化 + 标自身数值。

**踩坑**
- `tools/smoke.mjs` 的 canvas stub 是个 Proxy，未实现的方法统一返回 undefined，
  导致新用的 `ctx.measureText(...).width` 炸了。已在 makeCtx 里补 measureText（按 6px/字符估宽）。
  教训：这个 stub 只覆盖「无返回值的绘制调用」，以后在 render.js 里用任何**有返回值**的
  canvas API，都得先回 smoke.mjs 补 stub。
- 验证新曲线不能只看冒烟过没过，要单独查 `history` 里新键的非零点数（本次 198/144/170 均非零）。

## 待办（用户暂缓，未实施）：图例 `%` 对小白不友好

arhdhao 反馈看不懂 `sGC(%)` 里的 `%`。已解释清楚：%=激活度=酶的「开工率」
（酶台数固定，变的是活性；信使分子才是靠数量说话）。
但**承认这是设计缺陷**：量级一致 ≠ 单位一致 —— 同一 Y 轴上混了「浓度 / 分子个数 / 百分比」三种量纲，
只标个 `(%)` 不够。次要坑：激活度 100% 在 max=160 轴上只到 62.5% 高度，会系统性低估激活度。

四种改法（按代价递增，arhdhao 2026-09-07 选择「先不改」，随时可重启）：
1. 图例 `sGC(%)` → `sGC 激活度`（底部长条 1500px 宽，不缺这点字）
2. 端点数值带单位（`76%` vs `47`）
3. 图例加一行注解「实线 = 浓度/分子数，虚线 = 激活度」
4. 彻底分层：激活度三条单独占下半层矮图，各用 0–100% 轴（唯一能根治 62.5% 误导的办法，但要动绘图布局）
推荐 1+2+3 打包（<10 行改动），4 作为后备。
