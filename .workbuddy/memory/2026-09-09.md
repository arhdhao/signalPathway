## 读代码时发现的两条动力学性质（重要，后续调参会用到）

1. **本引擎的 `hill` 会让半程点右移，不是纯变陡。**
   引擎用嵌套形式 `(S/(S+K))ⁿ`（drive 再取幂），而非经典 Hill 的 `Sⁿ/(Kⁿ+Sⁿ)`。
   半程点由 `S = K·p/(1−p)`, `p = 0.5^(1/n)` 给出：
   n=1 → 1.00K ｜ 1.4 → 1.56K ｜ 1.6 → 1.84K ｜ 2.0 → 2.41K。
   ⇒ **调 `hill` 必须同步补 `K`，否则响应整体被往后推。**
   这一条 `04kinetics.ts` 的注释里没写。

2. **槽位竞争是「零级区近似」的竞争性抑制，不是标准米氏竞争式。**
   引擎：`v_cGMP = cap·[cGMP]/([cGMP]+[Sil])` —— 分母**没有 Km 项**；
   米氏竞争：`v = Vmax·[S]/(Km(1+[I]/Ki)+[S])`。
   ⇒ 等价于假设 PDE5 始终被底物占满。后果：更直觉、抑制剂效果被放大、
   但丢失「用高浓度底物平滑克服竞争」的过渡曲线。属有意选择的建模层级，不是 bug。

3. **振荡是结构性必然，不是配平问题。**
   `amplify(14) > slots(7.5)` ⇒ PDE5 即使 100% 激活，理论产能也只有 sGC 的 54%。
   sGC 若被持续点亮，需 `baseDecay` 补 (14−7.5)/0.022 ≈ 295 才平衡，远超红线 190
   ⇒ **不存在低于红线的高 cGMP 稳态** ⇒ 只能在两端之间摆动（极限环）。
   想压平振荡应该动这个比例（`slots`），而不是拧胜负阈值。

## 构建链讲解 + 两处待办发现（纯讨论，未改代码）

给 arhdhao 讲清了三件事（他自述小白，要求只讨论）：
① TS/JS 混用原理（tsc 擦类型 + allowJs 原样拷贝 → build/ 统一成 JS）
② 打包原理（依赖图拓扑排序 → 每模块包 IIFE → import/export 转查表/return → 注入模板占位符）
③ file:// 下 type=module 被 CORS 拦（origin=null）→ 必须打包或起 dev-server

**发现 1（已处理）**：`build/` 曾严重过期 —— src 拆成 nocgmp/ 子目录且文件加了数字前缀
（01view.ts…），但 build 里还是旧的 view.js，index.js 引 './view.js'。
若只跑 `node tools/build.js` 不打 tsc，会静默打包旧代码。
→ 已 `rm -rf build` + 重编，现 11 对 11 一一对应。
⚠️ 教训：tsc **不清理 outDir**，改名后旧产物会残留（不污染打包，因依赖图 DFS 够不着孤儿，
但目录会脏）。改名源文件后务必 `rm -rf build` 再编译。

**发现 2（待办，未修）**：跑 `node tools/balance.mjs` 会报
`MODULE_TYPELESS_PACKAGE_JSON` warning —— 根因是死结：
  · tools/build.js 用 require()，是 CommonJS → package.json **不能**有 "type":"module"
  · build/*.js 是 ESM → **希望**有 "type":"module"
两者冲突。当前仅性能开销（Node 需重新解析），结果正确，可无视。
根治方案（推荐 a）：
  a) `git mv tools/build.js tools/build.cjs` + package.json 加 "type":"module" + scripts 里改 .cjs
  b) build/ 下塞一个 {"type":"module"} 的 package.json（但 build 被 gitignore，不持久）
  c) 无视
