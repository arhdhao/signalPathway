## 〇、一句话定位

本文要在下面这个句子的地方撕开一个口子：

> 《细胞信号通路入门》第 5 站留了一句话 —— **「浓度决定强度，不是有或没有」**。
> 本文的任务，是把这句话**写成一行可以计算的式子**。

整篇文章沿三个层次推进，每一层都比上一层更“能落地”：

| 层次 | 问的问题 | 回答的形式 | 对应章节 |
|---|---|---|---|
| **定性** | 为什么浓度高了反应就快？ | 语言与比喻 | 一、二 |
| **定量** | 快多少？有没有上限？ | 公式与参数 | 三 |
| **可计算** | 怎么装进一台 10 Hz 的模拟器里？ | 离散规则 | 四、五 |

**一个贯穿全文的判断**：动力学参数的绝大部分麻烦，来自**混淆了“绝对速率”和“归一化比例”**。本文会反复回到这一点。

## 一、先分清「有多少」和「有多快」

### 1.1 浴缸：全文唯一的比喻

把 cGMP 想象成浴缸里的水：

```
龙头（sGC 合成）──流进──▶ ┃        ┃ ──流出──▶ 下水道（PDE5 降解）
                         ┃ 水位   ┃
                         ┃（浓度）┃
```

动力学研究的是**流速**，不是水位。但两者之间有一条唯一的铁律：

> **稳态（Steady State）＝ 流入速率 ＝ 流出速率。**

水位不变，不代表水不动 —— 只是进出相等。反过来，想改变水位，就必须**打破流速的平衡**。

这条铁律是后文所有分析的支点。药物之所以有用，往往不是因为它“加了水”，而是因为它**改变了某个流速**。

### 1.2 第一关的 cGMP 有几个出口

顺着这条路单列一遍，会发现一个容易被忽略的事实：

| 方向 | 来源 | 速率由什么决定 |
|---|---|---|
| **流入** | sGC 把 GTP 转成 cGMP（`r2`） | sGC 激活度、GTP 余量 |
| **流出 ①** | PDE5 水解（`r6`，槽位降解） | PDE5 激活度、底物之间的分摊比例 |
| **流出 ②** | cGMP 自然降解（`baseDecay`） | cGMP 自身的数量 |

**流出 ② 是看图时最容易漏掉的一条。** 拓扑图上大家盯着 PDE5（因为它戏剧性强），但每 tick 稳定流失的那 2.2% 往往才是决定“水位最终停在哪”的主力 —— 它是唯一**随浓度线性增长**的出口，浓度越高漏得越多。

### 1.3 消失的两种方式：零级 vs 一级

这是动力学最基础的分野，值得多花一分钟：

| 类型 | 速率式 | 特征 | 例子 |
|---|---|---|---|
| **零级（Zero-order）** | `v = k`（与浓度无关） | 每单位时间移除**固定量** | 酶被底物占满时（排队饱和） |
| **一级（First-order）** | `v = k·C`（正比于浓度） | 每单位时间移除**固定比例** | 自发分解、稀释、清除 |

**一级衰减 = 半衰期恒定。** 不管现在有多少，减半所需的时间都一样 —— 这是指数函数的定义属性。

本引擎里 `count` 的自然衰减就是一级的：

```
count ← count × (1 − baseDecay)      // 每个 tick 乘一次 —— 是乘法，不是减法
```

对应的连续形式是 `dC/dt = −k·C`，解为 `C(t) = C₀·e^(−kt)`。

> ⚠️ **最常踩的坑**：`baseDecay: 0.115` **不是**「每 tick 减 0.115 个」，而是「每 tick 减 11.5%」。
> 前者是零级（量纲：分子数/tick），后者是一级（量纲：1/tick）。两者行为完全不同：
> 零级会在有限时间内减到 0 并停住；一级永远逼近 0，却永远减不完。

所以用乘法而不是减法是有深意的：**乘法是指数解的精确离散化**，它在任意浓度下都保持“比例不变”这个语义；而 `count − 0.115` 会让低浓度下出现负数并提前归零。

### 1.4 把半衰期算出来

由 `count ← count × (1 − d)`，每 tick 的精确保留率是 `(1−d)`，故：

```
t½ = ln2 / (−ln(1−d))        ≈ ln2 / d    （d 很小时成立）
```

把第一关的数字代进去（`TICK_MS = 100`，1 tick = 0.1 秒）：

| 分子 | 字段 | 值 | 半衰期（tick） | 游戏内秒数 |
|---|---|---|---|---|
| `NO` | `baseDecay: 0.115` | 0.115 | 5.7 | **0.57 s** |
| `cGMP` | `baseDecay: 0.022` | 0.022 | 31.2 | **3.1 s** |
| `MLCP` | `decay: 0.085` | 0.085 | 7.8 | **0.78 s** |
| `PKG` | `decay: 0.05` | 0.05 | 13.5 | 1.4 s |
| `PDE5` | `decay: 0.03` | 0.03 | 22.8 | 2.3 s |
| `sGC` | `decay: 0.015` | 0.015 | 45.9 | 4.6 s |
| 西地那非 | `metabolism: 0.006` | 0.006 | 115.2 | **11.5 s** |

这张表值得盯着看三秒，因为**几乎每一个关卡设计意图都写在里面**：

- `NO` 的半衰期只有 0.57 秒 → 它**靠脉冲频率携带信息，而不是靠存量**。这解释了为什么 `pulse.period: 16` 这么关键。
- `MLCP` 的 `decay` 是全网最大（0.085）→ PKG 一停摆，它 0.78 秒就掉一半 → **Ca 立刻反弹**。这是故意的，目的是让“蒙一眼把 Ca 压下去”不算胜利。
- `sGC` 的 `decay` 最小，且 `buffTicks: 18` 期内衰减再乘 `0.35`（半衰期拉长到 13.2 秒），过期后乘 `2.0`（缩回 2.3 秒）→ **激活态有“维持期”和“崩塌期”两种截然不同的性格**。

> 💡 `decay`、`baseDecay`、`metabolism` 三者**数学形式完全一样**，都是一级衰减系数（1/tick）。区别只在语义：酶与激酶用 `decay`（失去活性），信使分子用 `baseDecay`（被清除），药物用 `metabolism`（被机体代谢）。

### 1.5 时间是被压缩过的

最后提醒一句：真实 NO 的半衰期是**秒级**，游戏里只有 0.57 秒 —— 时间尺度被整体压缩了。真实的 cGMP 回升、Ca 下降要几秒到几十秒，游戏里一局 200 秒跑完。

> ⚠️ 所以本文反复强调：**这套模型的数字不带物理单位，只带结构。** 你可以用它推断“加大 K 会让响应变迟钝”，但不能用它推断“cGMP 的真实浓度是多少”。

## 二、为什么速率会随浓度变：三个层层叠加的机制

浓度影响速率，其实由三个不同的原因叠起来。分开看很干净，混在一起就会迷惑。

### 2.1 第一层：碰撞（质量作用定律）

最朴素的一条：反应要发生，分子必须先撞上。**分子越多撞得越勤，反应越快。**

```
稀：  ●        ○              →  难得撞上一次
浓：  ●●○○●○●●○○●○           →  碰撞频繁
```

数学表达即**质量作用定律（Law of Mass Action）**：

```
A + B → 产物          v = k · [A] · [B]
A → 产物（自发）       v = k · [A]
```

`k` 是**速率常数（Rate Constant）** —— 剔除了浓度之后，“这个反应本身有多容易发生”。

这一层永远成立，是一条直线：**浓度翻倍，速率翻倍。**

### 2.2 第二层：饱和（酶的瓶颈）

但细胞里的反应绝大多数由**酶（Enzyme）**催化。而酶有个致命特性：**数量有限**。

```
Step 1：游离酶  E  +  底物 S  ⇌  ES      （结合）
Step 2：复合物  ES  →  E  +  产物 P      （转化）
```

关键在中间那个 `ES`：酶必须先“接单”才能干活，而它**同一时刻只能接一个**。

于是就有了经典的排队场景 —— 单人窗口的办事大厅：

```
底物很少时：  窗口大部分时间空着 → 来一个办一个，人越多办得越快
底物很多时：  窗口 100% 占满，外面排起长队 → 再多人来，处理速度也不动了
```

画出来是一条**矩形双曲线（Rectangular Hyperbola）**而不是直线 —— 这就是**米氏方程（Michaelis-Menten Equation）**：

```
                  Vmax · [S]
      v  =  ───────────────────
                  Km + [S]
```

这条曲线有三个性格截然不同的区段：

| 区段 | 条件 | 近似式 | 行为 |
|---|---|---|---|
| **一级区** | `[S] ≪ Km` | `v ≈ (Vmax/Km)·[S]` | 正比于 [S]，像直线 |
| **混合区** | `[S] ≈ Km` | 原式 | 过渡 |
| **零级区** | `[S] ≫ Km` | `v ≈ Vmax` | 与 [S] 无关，饱和 |

> 💡 一句话记住米氏行为：**低浓度时它装作一级，高浓度时它退化成零级。** 中间在哪里过渡，由 `Km` 说了算。

### 2.3 第三层：协同（S 形从哪来）

米氏曲线是**双曲线** —— 它一开始就有斜率，只是越来越平。但很多生物响应不是这样：它们在低浓度下**几乎没反应**，过了某个点突然起飞。这种 S 形（Sigmoidal）来自**协同性（Cooperativity）**。

典型场景：一个蛋白质有多个亚基、多个配体结合位点。第一个配体结合后引起**构象变化**，让第二个位点更容易结合 —— 这就是**正协同（Positive Cooperativity）**。

```
位点①很难结合  →  一旦进来，位点②变容易  →  位点③更容易
结果：          低浓度下几乎不动，一旦开闸就一起动
```

数学表达是**Hill 方程（Hill Equation）**（写成“被占满的比例”形式）：

```
                      [S]ⁿ
      θ  =  ───────────────────          θ：位点被占满的比例（0–1）
                   Kⁿ  +  [S]ⁿ
```

`n` 是**Hill 系数（Hill Coefficient）**，作用只有一个 —— **控制曲线有多陡**：

```
n = 1   →  双曲线（退化成米氏方程，无协同）
n > 1   →  S 形，正协同（阈值式开关）
n < 1   →  比米氏还平，负协同（无级调光）
```

> 🔬 **物理意义上，`n` 描述的是“开关”还是“旋钮”**：`n` 越大，响应越像开关（阈值明确、抗噪声）；`n` 越小，越像无级调光。生物系统普遍偏爱 `n > 1`，因为**开关能过滤噪声** —— 浓度的小幅抖动不会被误判成信号。细胞里几乎没有真正的二进制，只有足够陡的 S 形。

这和《入门》第 5 站那句“浓度就是信号强度”正好衔接：**S 形让“强度”这个词有了落点 —— 它不只是强弱，还包含一个门槛。**

### 2.4 三层叠起来的完整图景

```
第 1 层  碰撞          →  速率 ∝ 浓度          （永远成立的基础）
第 2 层  饱和（有限酶） →  出现天花板 Vmax，过渡位置由 Km 定
第 3 层  协同（多位点） →  曲线从双曲线弯成 S 形，陡度由 n 定
               ↓
真实的剂量-反应曲线 = 这三层叠加的结果
```

理解了这三层，下一节的参数表就不是死记硬背了 —— 每个参数都对应其中某一层的某一件事。

## 三、核心参数：每个到底在回答什么问题

这一节是全篇的字典。每个参数回答的问题都不同，**用错地方就是最常见的误诊**。

### 3.0 先来一张全景表

| 参数 | 回答的问题 | 量纲 | 在本项目的对应字段 |
|---|---|---|---|
| `k`（速率常数） | 反应本身多容易发生 | 视级数而定 | `decay` / `baseDecay` / `metabolism` |
| `Km`（米氏常数） | 速率到一半需要多少底物 | **浓度** | `K`（半饱和常数） |
| `Vmax`（最大速率） | 满负荷时最快能多快 | 浓度/时间 | `amplify`（合成侧）、`slots`（降解侧） |
| `kcat`（转换数） | 单个酶分子每秒处理几个底物 | 1/时间 | —（见 3.3，被吸收进 `slots`） |
| `kcat/Km` | 酶在稀底物下有多高效 | 1/(浓度·时间) | — |
| `n`（Hill 系数） | 响应有多陡、多像开关 | 无量纲 | `hill` |
| `Ki`（抑制常数） | 抑制剂结合靶点有多紧 | **浓度** | 隐含在竞争比例中（见 3.8） |
| `IC50` / `EC50` | 压一半 / 激一半需要多少药 | **浓度** | 剂量 `amount` 的概念来源 |
| `t½`（半衰期） | 多久消失一半 | 时间 | 由 `decay` 换算（见 1.4） |

**读表口诀** —— 拿到任何参数，先问两个问题：

> ① 它是**有单位的浓度 / 时间**，还是**无量纲的比例**？
> ② 它描述的是**一条饱和曲线**，还是**一条直线**？

这两个问题答错，后面就是盲调。

---

### 3.1 `Km` —— 半程点，还是亲和力？

**定义**：反应速率达到 `Vmax` 一半时所需的底物浓度。

```
      v ↑
Vmax ─ │          ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈
       │      ╭──────────────
Vmax/2 ┤──────╯
       │   ╭──
     0 └───┬──────────────────→ [S]
           ↑
          Km
```

**直觉**：`Km` 小 = 一点点底物就喂饱酶 = 酶“吃得少”；`Km` 大 = 得堆很多底物才跑起来。

| 场景 | 该不该用 Km |
|---|---|
| 判断酶在生理浓度下是否饱和 | ✅ 本职工作 |
| 粗略比较同族酶对同一底物的“胃口” | ✅ 可用 |
| 当作**结合亲和力** `Kd` 使用 | ⚠️ 有条件成立 |
| 比较两个机制不同的酶谁“更强” | ❌ 不够，还要看 `kcat` |

> ⚠️ **最常见的误解：Km ≠ 亲和力。**
> 严格的动力学推导给出 `Km = (k₋₁ + k₂) / k₁`，而真正的解离常数是 `Kd = k₋₁ / k₁`。
> 只有当**催化步骤远慢于解离**（`k₂ ≪ k₋₁`，即底物结合后很少被转化就又掉下来）时，两者才近似相等。
> 很多酶并不满足这个条件，它们的 `Km` 明显大于 `Kd`。看到文献写“Km 反映亲和力”，要当成粗略说法。

**在项目里**：`K` 就是 `Km` 的直接对应 —— `drive = count / (count + K)` 与 `θ = [S]/(Km+[S])` **同构**。NO 的 `K=30` 意味着：**要让 NO 的推动力到一半，需要 30 个单位的 NO。**

---

### 3.2 `Vmax` —— 产能的绝对天花板

**定义**：酶被底物完全饱和时的反应速率。它的来源是一个乘法结构：

```
      Vmax  =  kcat · [E]total
```

单个酶分子的快慢（`kcat`）乘上酶的总数（`[E]total`）。

**这个分解很重要**，因为它给出了两条完全不同的调参路径：

| 想让通量变大 | 改什么 | 生物对应 |
|---|---|---|
| 提高单个酶的效率 | `kcat` | 酶的别构激活 |
| 增加酶的数量 | `[E]total` | 上调表达 / 招募更多酶到膜上 |

> 💡 细胞调控**往往走第二条路**。瞬间改造所有酶的效率很难，但“多合成一批酶”或“把胞质里的酶搬到膜上来”是常规操作。这就是为什么上调这条通路时，见效快慢取决于转录和转运的速度，而不是取决于催化常数本身。

**在项目里**：`Vmax` 对应两个字段，方向相反：

| 方向 | 字段 | 第一关的值 | 单位含义 |
|---|---|---|---|
| 合成侧 | `r2.amplify` | `14` | 满负荷时每 tick 最多产 14 个 cGMP |
| 降解侧 | `r6.slots` | `7.5` | 满负荷时每 tick 最多处理 7.5 个底物 |

推导很干净：当 `drive = 1`（完全饱和）时，`made = amplify × 1 × jitter`；当 PDE5 满激活时，`cap = slots × 1`。**两者就是各自方向上的 Vmax，单位是“分子数 / tick”。**

---

### 3.3 `kcat` —— 单个酶分子的“手速”

**定义**：一个酶分子在饱和状态下，单位时间内转化多少个底物分子。单位 `1/时间`（如 `s⁻¹`）。

数值跨度极大：从碳酸酐酶的 `10⁶ s⁻¹` 量级，到某些调控酶的 `< 1 s⁻¹`。差别在目的不同 —— **代谢酶追求通量，信号分子不追求通量，追求节奏。**

**在项目里 `kcat` 被有意折叠掉了**，没有独立字段。原因见 3.2：`Vmax = kcat × [E]`，而本引擎只允许调节二者的乘积 `slots`。这是一个刻意简化 —— 引擎不管有多少拷贝的 PDE5、每个拷贝多快，只建模它们的**总产能**。

> ⚠️ 有得必有失：**“上调 / 下调酶的表达量”这类转录层面的调控在当前模型里无法表达**，因为它需要把 `[E]total` 单独拎出来当变量。这是模型的边界之一。

---

### 3.4 `kcat/Km` —— 催化效率，常被忽略的王者

在低底物条件下（`[S] ≪ Km`），米氏方程退化成：

```
      v ≈ (kcat/Km) · [E]total · [S]
```

所以 `kcat/Km` 是一个**表观二级速率常数**，描述“酶在底物稀少时抓住并转化底物的综合能力”。

它的价值在于**同时惩罚两种失败**：一个 `kcat` 高但 `Km` 也高的酶，和一个又快又抓得紧的酶，可能 `Vmax` 一样 —— 但在真实的稀底物环境里表现天差地别。

> 🔬 这是理解“为什么要谈效率”的关键：**细胞里的底物大多数时候远低于 `Km`**，酶基本跑在一级区。此时决定竞争力的不是 `Vmax` 而是 `kcat/Km`。只看 `Vmax` 会严重误判 —— 就像只拿最高时速评价一辆通勤车一样偏离用途。

**在项目里**：`slots` 与 `K` 的比值（虽然引擎把它们放在两处）构成本关降解侧的效率写照。给同样的 cGMP，PDE5 的实际表现取决于**它有多少产能**（`slots`）和**它要不要跟别人分摊**（竞争，见 3.7）。

### 3.5 Hill 系数 `n` —— 陡度，以及一个本项目特有的副作用

物理含义已在 2.3 讲过，这里补充**两个必须知道的警告**。

> ⚠️ **警告一：`n` 不等于结合位点数。**
> Hill 系数是从剂量-响应曲线**拟合出来的经验参数**。对于 `m` 个完全协同的位点，`n` 的上界是 `m`；但由于协同往往不完全、位点也不全等价，**实测 `n` 几乎总是小于位点总数**。
> 因此 `n` 应当读作“**表观协同程度**”，不能拿它反推蛋白质结构。

> ⚠️ **警告二（本项目特有）：调 `hill` 会把半程点整体右移。**
> 经典 Hill 方程是 `θ = Sⁿ/(Kⁿ+Sⁿ)`，半程点永远在 `S = K`。
> 但本引擎用的是**嵌套形式** —— 先把底物换算成 `drive`，再取幂：
> ```
> drive     = count / (count + K)      ← 第一步：米氏饱和
> intensity = drive ^ hill             ← 第二步：再取幂
> ```
> 两步合起来是 `(S/(S+K))ⁿ`，而经典 Hill 是 `Sⁿ/(Kⁿ+Sⁿ)` —— **两者不是一回事。**
>
> 后果：本引擎里 `hill` 越大，达到半程所需的 `count` 越高。由 `(S/(S+K))ⁿ = 0.5` 解出 `S = K·p/(1−p)`（其中 `p = 0.5^(1/n)`）：
>
> | `hill` | 半程点出现在 `count =` |
> |---|---|
> | 1.0 | `1.00 · K` |
> | 1.4 | `1.56 · K` |
> | 1.6 | `1.84 · K` |
> | 2.0 | `2.41 · K` |
>
> **所以调 `hill` 不能只顾着变陡 —— 它同时把响应整体往后推。** 想要“起点不变、只是更陡”，必须**同步把 `K` 往上补**。
> 这一条 `04kinetics.ts` 的注释里没有提，是读公式才能发现的性质。

**在项目里**：`r3`（cGMP→PKG）的 `hill = 1.6` 是全关最高。这不是装饰 —— 它让 PKG 成为一个有门槛的检测器：**少量 cGMP 点不亮它，必须靠“数量淹没”才行。** 这就是《机制介绍》里那句“需要数量淹没才高效激活”的量化写法。

### 3.6 `EC50` / `IC50` —— 药理学那一套，为什么不能当常数

| 参数 | 定义 | 谁关心 |
|---|---|---|
| `EC50` | 产生**半数最大效应**所需的激动剂浓度 | 药效评价 |
| `IC50` | 产生**半数最大抑制**所需的抑制剂浓度 | 先导化合物筛选 |

它们看起来很像 `Km`（都是“半程点”），但有一个根本差别：

> ⚠️ **`IC50` 不是本征常数，它依赖实验条件。** 同一个抑制剂，换个底物浓度，`IC50` 就变了。
> 本征的那个常数叫 **`Ki`**。竞争性抑制下两者的关系由 **Cheng-Prusoff 方程**给出：
> ```
> IC50  =  Ki · (1 + [S]/Km)
> ```
> 也就是说：底物浓度越高，抑制剂显得越弱 —— 因为它在跟底物**抢同一个位置**，而底物人多势众。

这就是为什么文献里西地那非的 `IC50` 数值在不同论文间能差好几倍：**它们是在不同的 `[S]` 下测的。** 所以看到纳摩尔量级这种数字，要当作“数量级参考”，而不是可以填进模型的值。

> 💊 读文献的实用口诀：**看到 `IC50` 先问 `[S]/Km` 是多少，再拿它跟别的论文比。** 否则你比较的是不同的实验，而不是不同的化合物。

### 3.7 `Ki` 与抑制类型 —— 竞争性抑制到底长什么样

这是本项目的机制核心，值得把四种类型摆全：

| 类型 | 结合哪里 | 对 `Vmax` | 对 `Km` | 能否被高底物克服 |
|---|---|---|---|---|
| **竞争性** | 只结合游离酶的活性位点 | **不变** | **变大** ×`α` | ✅ 能（底物把它挤走） |
| **非竞争性** | 结合活性位点以外的部位 | **变小** | 不变 | ❌ 不能 |
| **反竞争性** | 只结合 `ES` 复合物 | 变小 | 变小 | ❌ 不能 |
| **不可逆** | 共价结合，酶永久报废 | 变小（等效 `[E]↓`） | 不变 | ❌ 不能 |

其中 `α = 1 + [I]/Ki`。

**关键点**：竞争性抑制的机制是 —— `Vmax` **一点没变**。加再多底物，理论最大速率还是那个数（活性位点本来也没坏，只是被占着，能被挤走）。变的是**达到半程所需的底物浓度**。

> 💡 记住竞争性抑制的一句话：**它不是让机器变慢，是让机器更难排队。** 机器还是那台机器，只是你得排更长的队才轮得到。

这正好解释了西地那非为什么属于“松刹车”而不是“踩油门”（呼应《入门》第 9 站）：它**一个单位的 cGMP 都没有多造**，只是让 cGMP 在降解通道里排队更难了。

**在项目里**：竞争通过**槽位瓜分**实现，而不是通过一个 `Ki` 字段：

```
cap    = slots × (PDE5.activation / 100)        // 酶的总产能
份额   = cap × count_i / Σ(count)               // 按数量比例瓜分
```

于是 cGMP 实际拿到的降解能力是：

```
                       [cGMP]
      v_cGMP  =  cap · ─────────────────
                       [cGMP] + [Sil]
```

对比米氏竞争性抑制的标准式：

```
                    Vmax · [S]
      v      =  ──────────────────────
                  Km·(1 + [I]/Ki) + [S]
```

> 🔬 **一个必须点破的差异**：标准式的分母里有 `Km`，本引擎的分母里没有。
> 换句话说，**本引擎的槽位竞争是“零级区近似”的竞争性抑制** —— 它假设 PDE5 **始终被底物占满**（总底物浓度远高于 `Km`），于是 `Km` 项被忽略，`Vmax` 直接按数量比例分。
>
> 三个后果：
> 1. **更直觉**：玩家看到的是“抢座位”，不需要理解 `Km`
> 2. **更狠**：少了 `Km` 这个缓冲项，多一个占座者就直接分走一份固定产能 —— 抑制剂效果被放大
> 3. **丢失的现象**：真实的竞争性抑制可以被高浓度底物平滑地克服；本模型的瓜分比例由**数量比**决定，缺少 `Km` 提供的那条过渡曲线
>
> 这不是 bug，是**有意选的建模层级** —— 对着“定性拓扑推演”这个定位，清晰比精确更值钱。

---

### 3.8 `Ki` 在引擎里上哪去了

注意一个很有意思的事实：**引擎里没有 `Ki` 这个字段。** 竞争性抑制完全由三条通用规则涌现：

```
① Sildenafil 与 cGMP 共享 PDE_Target 标签   →  有资格进候选池
② 槽位按数量比例瓜分                        →  分摊产能
③ degradable: false                         →  占座但不被清除（长期占位）
```

这三条组合起来，等价于“一个 `Ki` 很小、且不容易被代谢掉的竞争性抑制剂”。

> 🎉 值得品味的一点：**`Ki` 的信息被表达了，但没有作为一个参数出现。** 这是把机制做到“涌现”层面的典型例子 —— 想换一种药效更强的抑制剂，改 `amount` 和 `metabolism` 就行，不用给引擎加分支。

强度由**数量比**决定（`count` 大 → 份额大 → 抑制强），持续时间由 `metabolism` 决定（半衰期 115 tick ≈ 11.5 秒）。这两个 knob 合起来，就是药理学上说的“效价”和“作用时长”。

## 四、把一个连续的生化世界变成可计算的：三步降维

这是全文的技术核心。三件事必须依次发生：**离散化时间 → 归一化浓度 → 把速率换成骰子**。

### 4.1 第一步：离散化时间 —— 微分方程变差分方程

真实动力学写在连续时间里：

```
      dC/dt  =  f(当前状态)
```

计算机只能一步步跳。最简单的做法是把导数换成差分（**前向 Euler 法**）：

```
      C(t + Δt)  =  C(t) + f(C) · Δt
```

这条路有个著名陷阱：**步长太大就会炸。** 以一级衰减为例：

```
加法形式（Euler）：  C ← C − k·C·Δt  =  C · (1 − k·Δt)
```

如果 `k·Δt > 1`，`(1 − k·Δt)` 变成负数 → 下一 tick 浓度反向 → 再下一 tick 更大 → **数值振荡发散**。

本引擎回避了这个坑，用的是**乘法形式**：

```
乘法形式（本引擎）：  C ← C × (1 − d)
```

只要 `0 < d < 1`，结果就永远非负、永远单调 —— **无条件稳定**。

> 💡 这不是巧合，而是选对了离散化的对象：**乘法形式是对指数解 `C(t) = C₀·e^(−kt)` 的精确采样**，而不是对导数的粗糙近似。两者之差在大步长下才显现：加法形式在 `d > 1` 时炸掉，乘法形式永远平滑。
> 代价是 `(1−d)` 与 `e^(−kΔt)` 有微小差异（也就是 1.4 里那个 `-ln(1−d)` 修正项），换算时补偿一下就行。

**在本项目里**：步长钉死为 `TICK_MS = 100`（10 Hz）。理由是**可复现性** —— 帧率随设备而变，逻辑若跟着帧走，同一套参数在 60 Hz 和 144 Hz 屏幕上会推出不同的故事。

### 4.2 第二步：归一化 —— 把浓度变成 0–1 的推动力

这是降维中最优雅的一步。注意米氏方程可以改写：

```
      v         [S]                 [S]
    ─────  =  ─────────  =  ────────────────
     Vmax       Km + [S]        [S] + Km
                                 ↑ 这一项就是 drive
```

右边是**无量纲的 0–1 比例**，左边是 `v/Vmax`。也就是说：

```
      drive  ≡  v / Vmax  ≡  当前速率占满负荷的比例
```

这正是引擎里那个核心概念 **`drive`（推动力）**：

| 分子类型 | `drive` 公式 | 来源 |
|---|---|---|
| 数量驱动（`NO` / `cGMP` / 药物） | `count / (count + K)` | 米氏饱和曲线本身 |
| 激活度驱动（`sGC` / `PKG` / `MLCP` / `PDE5`） | `activation / 100` | 已经是归一化比例 |

**归一化带来三个实打实的好处**：

1. **无量纲** → 所有节点可以横向比较，不用担心单位换算
2. **天然有上限** → 不可能超过 1，**放大器永远不会失控**
3. **可直接当概率或强度用** → 跳到第三步时不需要再做变换

> ⚠️ 一个语义提醒：**第二种形式（激活度驱动）其实省略了一层** —— 它没有自己的 `K`，因为它假定“酶的激活度已经代表了它当下的产能”，不需要再经过一次底物饱和。这隐含假设了底物（GTP）充足；GTP 不足的情况由单独的 `budget/gtpCost` 封顶处理（见 4.4）。

### 4.3 第三步：把速率换成骰子 —— ODE vs Gillespie vs 本项目

确定了速率之后，还剩最后一个选择：**这是确定的，还是随机的？**

| 路线 | 怎么算 | 特点 | 适合 |
|---|---|---|---|
| **ODE（常微分方程）** | 对 `dC/dt` 数值积分 | 确定性，光滑曲线 | 分子数成千上万，涨落可忽略 |
| **Gillespie（随机模拟）** | 抽样“下一次发生哪个反应” | 随机，精确 | 分子数极少，离散效应显著 |
| **本项目：骰子** | 每 tick 按概率判定是否命中 | 随机，近似 | 定性推演 + 可玩性 |

本引擎的做法（`_resolveReaction`）：

```
① 标签匹配      from.tags ∩ to.tags ≠ ∅      →  确定这一跳有没有资格发生
② 掷骰子        chance = 宽度 × drive^hill     →  这一 tick 运气如何
③ 挂 Buff       delta  = power × drive^hill    →  命中的话有多强
④ 乘数增量      made   = amplify × drive^hill  →  produce 专用：产多少
```

**为什么这是合法的？** 因为**期望值守恒**。每 tick 的期望增量大致是：

```
      E[Δ]  ∝  chance × intensity × power
```

多 tick 平均下来，它收敛到确定性的速率曲线 —— 这就是大数定律。所以：

> 💡 骰子求解器的**平均值等价于 ODE 的解**，差别在于**单次推演保留了方差**。
> 这份方差不是噪声，是设计：**它让每一局都不一样，让玩家说得出“刚才那一把 PDE5 早醒了 2 秒”。** 换成 ODE，同一套参数永远推出同一条曲线，游戏就没有重玩性了。

代价也要写清楚：**丢失了 Gillespie 的精确涨落结构。** 比如“两个分子同时低到阈值以下”这种联合涨落，骰子模型刻画不了。对着定性教学的目标，这个代价可以付。

### 4.4 别忘了质量守恒：能量是一条硬约束

教科书里 `Vmax` 是个常数，但它隐含了“底物供应无限”。真实细胞不是。**合成 cGMP 要消耗 GTP。**

本引擎的处理：

```
budget = pools[costPool]                       // 当前资源余额
supply = budget > 0 ? 1 : 0                    // 有货才开工
made   = amplify × intensity × jitter × supply  // 基础产量
made   = min(made, budget / gtpCost)            // ⭐ 关键：不能透支
pools[costPool] −= made × gtpCost
```

那个 `min` 就是**离散世界里质量守恒**的表述：造不出资源不支持的产物。

> 💡 这个 `min` 不只是一条防错逻辑，它定义了**能量不足时的行为品格**：
> **平滑衰减，而不是断崖之后凭空续命。** 池子只剩 2 点时产量就是 2 点能支撑的量，而不是先白嫖 100 个再归零。这让“能量枯竭”表现为渐进的衰弱感，而不是突兀的失败。

**由此还能推出一条必须遵守的配置约束**（呼应《参数调参清单》4.1 的血泪教训）：

```
可持续的产能上限  =  poolsRegen.GTP / gtpCost  =  3.0 / 1.0  =  3.0 单位/tick
```

也就是说，**本关能长期维持的 cGMP 生产只有 3.0/tick**，而满负荷理论值是 `amplify = 14`。这 4.7 倍的差距正是“猛灌硝酸甘油会饿死”的原因 —— 短时超额 OK，长期超支必破产。

### 4.5 一张对照表：真实 → 模型

把上面的降维过程压缩成可以直接对照的一张表：

| 真实世界的量 | 数学表达 | 本项目的对应物 | 落在哪一层 |
|---|---|---|---|
| 浓度 `[S]` | 浓度单位 | `count`（数量驱动）/ `activation`（酶） | 运行时状态 |
| 半饱和常数 `Km` | 浓度 | `K` | ④ KINETICS |
| 归一化速率 `v/Vmax` | 0–1 | **`drive`** | `engine.ts` 计算属性 |
| 最大速率 `Vmax` | 浓度/时间 | `amplify`（合成）/ `slots`（降解） | ④ KINETICS |
| 协同性 `n` | 无量纲 | `hill`（**注意 3.5 的右移副作用**） | ④ KINETICS |
| 降解常数 `kdeg` | 1/时间 | `decay` / `baseDecay` / `metabolism` | ④ KINETICS |
| 竞争性抑制 `Ki` | 浓度 | 标签 + `degradable:false` + 数量比（**涌现**） | ②③ 跨层 |
| 结合特异性 | 结构化学 | **标签系统**（`tags` 交集） | ③ INTERACTION |
| 底物供应限制 | 质量守恒 | `pools` + `costPool` + `gtpCost` | ⑤ GAME |
| 确定性 vs 随机 | ODE / SSA | **骰子 `rng.roll()`** | `engine.ts` 机制 |

## 五、读懂具体的一关：用上面的知识反推设计意图

这一节把动力学当望远镜，回头看这一关为什么这么配。**结论全部来自 `04kinetics.ts` 里公开的参数，不需要跑代码。**

### 5.1 为什么这关一定会振荡

《参数调参清单》坑 3 说“极限环震荡是特性，不是 bug”。动力学可以给出更硬的理由。

**论据一：清除能力存在结构性劣势。**

```
合成侧上限 Vmax_合成  =  amplify  =  14.0  单位/tick
降解侧上限 Vmax_降解  =  slots    =   7.5  单位/tick（还得 PDE5 满激活才行）
```

**即使 PDE5 做到 100% 激活，它的理论产能也只有 sGC 的一半多一点。** 这意味着：一旦 sGC 被持续点亮，PDE5 这边的负反馈**在结构上就压不住**。

**论据二：唯一的救兵是 `baseDecay`，但它要等到浓度很高才给力。**

凑一下，假设 sGC 被持续点亮（产量顶到 14/tick），看 cGMP 能稳在哪：

```
需要清除 14/tick
  PDE5 满激活贡献：        7.5
  剩下要 baseDecay 补：     6.5   →   需要 C = 6.5 / 0.022 ≈ 295
```

**295 远高于红线 `190`。** 于是得到一个干脆的结论：

> **`sGC` 若被持续点亮，这条通路找不到任何低于红线、且 PDE5 仍然活跃的稳态 —— 玩家将死于脱靶毒性（`toxicity`）。**

**论据三：既然高浓度的稳态不存在，系统只能在两端之间来回摆动。**

```
cGMP 涨  →  PKG 亮  →  PDE5 亮  →  降解力压过合成  →  cGMP 掉
   ↑                                                        ↓
   │                                          PKG 暗  ←  PDE5 衰减
   └────  cGMP 又涨  ←  降解力退潮  ←────────────┘   （decay 0.03，半衰期 2.3 s）
```

这就是**极限环（Limit Cycle）**：一个由「负反馈 + 延迟」自发维持起来的周期运动。

**延迟从哪里来？两个来源叠加**：

1. **双缓冲的 1 tick 滞后**（《机制介绍》1.4 讲的那个整体设计）
2. **PDE5 自身的惯性**：它的 `decay` 是全关最小的之一（0.03），`buffTicks` 却是最长的（26）→ **一旦被点着就烧很久，很难很快退下来**

> 🎉 所以“必定振荡”不是配平没配好，而是 `amplify(14) > slots(7.5)` 这种**结构性不对称 + 反馈延迟**推出的必然结论。这也是《参数调参清单》说“压平它 = 抹掉关卡最核心的戏剧性”的原因。
> 反过来说，若真想压平，**该动的是这个比例**（把 `slots` 提到接近或超过 `amplify`），而不是去拧胜负判定的阈值。

### 5.2 为什么 MLCP 的 `decay` 是全网最大

`MLCP.decay = 0.085` → 半衰期仅 **0.78 秒**。这是刻意的：

```
PKG 还在高歌  →  MLCP 跟得上  →  Ca 被压住
PKG 一哑火    →  MLCP 0.78 秒就掉一半  →  Ca 立刻反弹
```

它直接保证了胜利条件不会被偷走：

```
胜利条件：Ca ≤ 45 且【连续】保持 50 tick（5 秒）
```

因为 MLCP 衰减极快，**一次偶然的冲击没法把 Ca 压住 5 秒**。必须让上游保持通畅，形成持续压制 —— 这正是要教的那件事：**瞬时值和稳态是两回事。**

### 5.3 三种死法，各自对应一类动力学事故

| 死法 | 动力学机制 | 由参数读出的触发条件 |
|---|---|---|
| **② 能量枯竭** `starvation` | **入不敷出** —— 长期产出速率超过再生速率 | 硝酸甘油叠加后 sGC 被猛点亮，合成速率远超 3.0/tick 的再生预算，`pools.GTP` 被逐步榨干（见 4.4） |
| **③ 脱靶毒性** `toxicity` | **清除能力被压到低于合成能力**，且没有一个够低的稳态能承接 | 西地那非占座 → cGMP 分到的降解份额下降 → 净积累越过红线 `190`（见 5.1 论据二） |
| **④ 干预失效** `timeout` | **系统卡在极限环里，从来进不了稳区** | 什么都不做时的默认命运：负反馈周期性反扑，Ca 永远压不住连续的 5 秒 |

> 💡 三种死法恰好对应动力学的三类失败：**资源失衡（流向坏了）、参数失衡（量级坏了）、结构失衡（拓扑决定了低稳态不可达）。** 这个分类法也可以拿来给新关卡构思新的失败模式。

### 5.4 为什么西地那非“必须依赖” NO 的存在

《参数调参清单》特意标注了一句：“药效依赖 NO 存在，西地那非本身不产生信号。” 动力学上这是显然的：

```
cGMP 只有一个入口：sGC 合成（需要 NO 点亮 sGC）
西地那非只作用于出口：压低 PDE5 抢走 cGMP 的份额
        ↓
出口堵住了，但入口没水 —— 浴缸照样是空的
```

临床推论也很干净：**内皮功能障碍、NO 源不足的人，西地那非效果会明显变差。** 这不是引擎的限制，而是**真实药理的结论** —— 模型忠实传达了这一点。

### 5.5 现象 → 该动哪个参数

最后给一张排障清单，全部呼应第三节的拆解：

| 观察到的现象 | 动力学解读 | 该动哪个参数 |
|---|---|---|
| 响应太迟钝，浓度要堆很高才动 | `Km` 太大（也可能是 `hill` 造成的右移） | `K` ↓；若刚调过 `hill`，反向补偿 `K` |
| 高低浓度拉不开差距（像开关） | **`n` 太大** | `hill` ↓ —— **而不是去减 `power`** |
| 响应够快但幅度不够 | `Vmax` 不足 | `amplify` ↑（注意 GTP 预算会同比吃紧） |
| 信号一闪就过，留不住 | 衰减太快或 Buff 太短 | `decay` ↓ / `buffTicks` ↑ |
| 信号下不来，一直挂着 | 衰减太慢 | `decay` ↑ —— 注意 `MLCP` 就是靠“快速反弹”守胜负门槛的 |
| 负反馈压不住主线 | 清除侧 `Vmax` 偏低 | `slots` ↑（会直接改变这一关的戏剧性强弱） |

> ⚠️ 最后一行再提醒一次：**《参数调参清单》把 `slots` 列为已知的难度分水岭。** 看完 5.1 应该明白为什么 —— 它不只是“降解快慢”，它决定了这个负反馈环**到底有没有一个可达的稳态**。改它等于重新设计这一关。

## 六、容易搞混的几件事

承接《入门》第 10 站的写法，把动力学里的高频误解打包：

**① 速率 ≠ 浓度**
浴缸的水位和流速是两件事。**稳态时浓度不变，但流动一刻没停。** 看到“浓度稳定”不要以为“没有反应在发生”。

**② `Km` ≠ 亲和力**
`Km = (k₋₁+k₂)/k₁`，`Kd = k₋₁/k₁`。只有 `k₂ ≪ k₋₁` 时才相等。“Km 反映亲和力”是粗略说法。

**③ Hill 系数 ≠ 结合位点数**
`n` 是从曲线拟合出来的表观协同程度，通常是位点数目的**下界**。

**④ `IC50` ≠ `Ki`**
`IC50` 依赖实验的底物浓度（`IC50 = Ki·(1+[S]/Km)`），不能跨论文直接比较。`Ki` 才是本征常数。

**⑤ 竞争性抑制不改 `Vmax`，改的是表观 `Km`**
这是区分抑制类型最快的判据：“酶没坏，只是排队更难了。”

**⑥ 本项目的 `hill` 会让半程点右移**
因为公式是 `(S/(S+K))ⁿ` 而不是经典的 `Sⁿ/(Kⁿ+Sⁿ)`。调 `hill` 时要连 `K` 一起补偿（详见 3.5）。

**⑦ 引擎里的数字是无量纲刻度，不是化学数据**
`count`、`activation` 不用说，连 `K` / `power` / `band` **都不带物理单位**。它们的目的只有一个 —— 保证**趋势正确、相对大小可比**。别拿文献浓度去校验它们。

**⑧ 本机的槽位竞争是“零级区近似”**
它假设酶始终被底物占满，丢掉了标准米氏式里的 `Km` 缓冲项。这让抑制剂效果被放大、也更直觉，但不再能复现“用极高浓度底物平滑地克服竞争”的那条过渡曲线。

## 想亲手验证？

《模拟机制介绍》第六节给了调试出口。配合本文可以这样玩：

```javascript
// 控制台可用：__sim
__sim.sim.node('cGMP').count       // 看浓度 C
__sim.sim.node('cGMP').drive       // 看归一化推动力 —— 对应本文的 drive
__sim.sim.node('PKG').activation   // 看酶的激活度
__sim.sim.sim.pools.GTP            // 看能量余额（资源约束，见 4.4）
```

推荐三个验证动作：

1. **验证饱和**：把 `cGMP` 的 `K` 改大（比如 62 → 300），会发现同样的数量推出来的 `drive` 明显变小 —— 这就是 3.1 里 `Km` 的含义。注意这是 ④ KINETICS 的参数，属 C 档，改完要跑验证脚本。
2. **验证 Hill 的右移**：把 `r3` 的 `hill` 从 1.6 提到 2.5，会发现 PKG **更难被点亮**（不只是更陡）—— 这就是 3.5 警告二的那个副作用。想要“起点不变只变陡”，得把 `cGMP` 的 `K` 同步往上补。
3. **验证 Vmax 不对称**：对着 `__sim.sim.pools.GTP` 的下降速度，看它是否突破了 4.4 算出的“可持续上限 3.0/tick”—— 用硝酸甘油叠加试最快。

改完记得走全回归：`npm run check`（改参数后先 `npm run build:ts`，因为配平脚本吃的是 `build/` 产物）。

## 延伸阅读

本文有意没有展开的方向（按推荐顺序）：

1. **更多酶促反应模型** —— 双底物机制（Ping-Pong / 顺序机制）、产物抑制、pH 与温度依赖。真实信号通路里多底物反应很常见。
2. **Gillespie 随机模拟** —— 本项目的远期替换方向。读懂本文 4.3 那张三路线对照表之后，就能看懂 `04kinetics.ts` 顶部那段关于求解器替换的注释为什么那么写。
3. **控制系统视角** —— 把负反馈看成控制器，用环路增益、相位裕度重新推导第 5.1 节的振荡分析。这么做过一次之后，PID 控制器那套行为会变得非常自然。
4. **药代动力学（PK）与药效学（PD）** —— 本文默认药物浓度是阶跃给定的，没有建模吸收、分布、代谢、排泄。西地那非的 `metabolism: 0.006` 只是其中最简单的一阶消除。

这些都超出了“读懂这套模拟器”的范围，本文就此收住。
