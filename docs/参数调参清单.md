# 参数调参清单

> 面向：项目所有者 & 未来关卡作者
> 对应代码：`src/pathways/nocgmp.js`（关卡数据）、`src/engine.js`（引擎）、`tools/`（验证工具）
> 当前口径：第一关 NO–sGC–cGMP–PKG–PDE5

这份清单回答一个问题：**哪些参数可以随手改，哪些一改就会让模拟结果变味。**

---

## 一、四档分类速查

| 档位 | 含义 | 改完之后 |
|---|---|---|
| 🟢 **A 档** | 纯体验 / 外观，不参与数值运算 | 直接玩，不用验证 |
| 🟡 **B 档** | 有余量，但有配套约束 | 对照清单自检即可，可选择性跑冒烟 |
| 🔴 **C 档** | 与模拟结果强耦合 | **必须**跑 `balance` / `sweep` 验证 |
| ⛔ **D 档** | 结构性机制，改了就不是这个模型了 | 原则上别动；要动请重新设计 |

## 二、🟢 A 档 · 放心调（不参与数值运算）

改这些不会让模拟结果有任何变化，纯粹是"好不好看 / 好不好读"。

| 参数 | 位置 | 当前值 | 说明 |
|---|---|---|---|
| `canvas: {w, h}` | 关卡顶层 | 1000 × 400 | 逻辑坐标，渲染层按容器自动缩放 |
| `nodes[].x / y` | 各节点 | — | 拓扑图坐标，随便挪 |
| `nodes[].color` | 各节点 | — | 配色 |
| `nodes[].name / cn / desc` | 各节点 | — | 名称与档案文案（**教学文本，改内容要自己把关语义**） |
| `drugs[].color / icon / en` | 道具 | — | 外观 |
| `lessons[]` | 关卡顶层 | 4 条 | 结算窗小知识 |
| `brief / hint / subtitle` | 关卡顶层 | — | 关卡说明文案（⚠️ 若改了 `goal.hold`，记得同步 `brief` 里写的秒数） |
| `reactions[].waypoints` | r5 | — | 连线拐点，纯绘制 |

## 三、🟡 B 档 · 可调，但注意配套

这类参数本身有宽松余量，但和别的东西绑着，改了要顺手检查一下。

| 参数 | 位置 | 当前值 | 配套约束 |
|---|---|---|---|
| `timeout` | 关卡顶层 | `1200`（120 秒） | ① 必须 **大于** 正常通关时间（正解约 40 秒，余量充足）<br>② 必须 **≤** `tools/balance.mjs` 的 `maxTicks`（现 1300），否则测试会提前截断、误报"未结束"<br>③ 它决定"不干预"场景能否走到超时判负，所以不是完全无害 |
| `drugs[].charges` | 道具 | 西地 2 / 硝甘 3 / ODQ 1 / 能量 2 | 影响容错与难度，不改机制。改了顺手重跑 `balance` 看场景是否仍成立 |
| `drugs[].hotkey` | 道具 | 1–4 | 纯按键绑定 |
| `gtp` 道具的 `effects[].amount` | 道具 | 400 | 与 `pools.GTP` 池容耦合：池容改了，这个要同比缩放，否则"续命"效果失衡 |

## 四、🔴 C 档 · 慎调（与模拟结果强耦合）

**这一档改完必须跑验证脚本。** 下面按"踩坑风险"从高到低排列。

### 4.1 判定层（最容易让游戏"不成立"）

| 参数 | 位置 | 当前值 | 为什么敏感 |
|---|---|---|---|
| `goal.hold` | 关卡顶层 | `30`（3 秒） | 胜利所需的稳态时长。**太短** → 乱灌药靠 Ca 短暂下探就能蒙赢；**太长** → 由于极限环震荡，连正解都拿不到连续达标，变成谁都赢不了。当前值偏短，是"乱灌必胜"的元凶之一 |
| `goal.target` | 关卡顶层 | `45`（Ca 阈值） | 胜利阈值，直接定义难度 |
| `redline.cGMP` | 关卡顶层 | `190` | 双重身份：既是"脱靶毒性"死法阈值，**也是胜利安全门的判定条件**。太高 → 过量不死；太低 → 正常治疗也被判毒，正解反而通不了关 |
| `pools.GTP` | 关卡顶层 | `1000` | 能量池容量，决定"能量枯竭"死法能否触发 |
| `poolsRegen.GTP` | 关卡顶层 | `3.0` | ⚠️ **与池容强耦合，且必须 ≥ 本底合成消耗速率**。曾经试过 600/1.2，结果连基础 sGC 本底合成都把池子烧穿，**所有玩法全部饿死、谁都通不了关** |

> **血泪教训**：`pools` 和 `poolsRegen` 必须一起看。判断标准是——不加任何药时，GTP 应当大致持平或缓慢下降，绝不能持续跌到个位数。可以用 `tools/balance.mjs` 的 idle 场景看 `GTP` 列。

### 4.2 宏观指标（Ca 的动力学）

| 参数 | 位置 | 当前值 | 为什么敏感 |
|---|---|---|---|
| `metrics[].drain` | Ca | `3.2` | 效应器把钙泵出的速率。Ca 的均衡点大致是 `base − drain/restore`，改它等于直接改写"Ca 到底能降到多少" |
| `metrics[].restore` | Ca | `0.045` | Ca 向基线回归的速率，同上 |
| `metrics[].base` | Ca | `100` | Ca 静息基线 |

### 4.3 反应边（信号传导的主力参数）

| 参数 | 位置 | 当前值 | 为什么敏感 |
|---|---|---|---|
| `reactions[].band` | r1–r5 | `[0,58]` 等 | **真正参与运算的命中频段**（注意：不是节点上的 `band`，见第六节）。决定命中概率 |
| `reactions[].hill` | r1 `1.4` / r3 `1.6` / r5 `1.4` | — | 协同系数，决定响应曲线的 **S 形陡峭度**。经验：**要拉开"有反应/没反应"的对比度，应该调 hill，而不是加大 power** |
| `reactions[].power` | r1 22 / r3 42 / r4 48 / r5 30 | — | 单次命中的激活力度。量级失控会把节点变成"开关"（剂量-反应曲线被压平） |
| `r2.amplify` | sGC→cGMP | `14` | cGMP 产量基数，直接决定 cGMP 浓度与 **GTP 消耗速率** |
| `r2.gtpCost` | sGC→cGMP | `1.0` | 单位产出能耗，与池容 / 再生三者强耦合 |
| `r6.slots` | PDE5→cGMP | `7.5` | PDE5 槽位总额。**已知是难度的分水岭**（历史配平结论），直接决定负反馈强度与西地那非的有效性 |

### 4.4 节点参数

| 参数 | 位置 | 当前值 | 为什么敏感 |
|---|---|---|---|
| `buffTicks` | sGC 18 / PKG 20 / MLCP 12 / PDE5 26 | — | Buff 持续时间。Buff 期内衰减慢、过期后加速回落（引擎里是 `decay × 0.35` vs `decay × 2.0`），所以它直接决定"激活能维持多久" |
| `decay` | sGC .015 / PKG .05 / MLCP .085 / PDE5 .03 | — | 激活度衰减。**MLCP 的 decay 最大（.085）是刻意的** —— PKG 一哑火，Ca 立刻反弹 |
| `baseDecay` | NO .115 / cGMP .022 | — | 信使分子自然降解，决定信号能持续多久。NO 的很大（.115）对应"半衰期极短，靠频率而非存量" |
| `K` | NO 30 / cGMP 62 / 西地那非 200 | — | 半饱和常数，决定"得多大数量才推得动下游"。cGMP 的 K=62 是"数量淹没"机制的量化表达 |
| `metabolism` | 西地那非 | `0.006` | 药物代谢速率，决定西地那非**占座多久** ⚠️ 注意：药效依赖 NO 存在，西地那非本身不产生信号 |

### 4.5 药物强度

| 参数 | 位置 | 当前值 | 为什么敏感 |
|---|---|---|---|
| 西地那非 `spawn.amount` | drug | `620` | 投放的诱饵数量，决定**占座比例**。太少 → 抢不过 cGMP，无效；太多 → 必然把 cGMP 顶到红线 |
| 西地那非 `metabolism` | drug | `0.006` | 同节点参数，占座时长 |
| 硝酸甘油 `factor` | drug | `2.0` | NO 脉冲幅度放大倍数，决定"过量冲击"强度 |
| 硝酸甘油 `periodScale` | drug | `0.55` | 脉冲周期压缩，决定冲击频率 |
| 硝酸甘油 `ticks` | drug | `90` | 药效持续时长 |
| ODQ `ticks` | drug | `70` | 沉默 sGC 的时长，决定"通路熄火"场景是否成立 |

## 五、⛔ D 档 · 结构性，别动

这些不是"参数"，是**模型的定义**。改了就等于换了个游戏。

| 参数 | 位置 | 说明 |
|---|---|---|
| `nodes[].tags` | 各节点 | 标签密码体系（`NO_Signal` / `cGMP_like` / `PKG_dock` / `PDE_Target`），**决定谁能碰谁**。改一个标签，整张拓扑的连通性就变了 |
| `reactions[].slotTag` | r6 | 槽位识别标签，与 `PDE_Target` 绑定，是竞争性抑制的基础 |
| `reactions[].effect` | 各反应 | activate / produce / consume / inhibit 的语义 |
| `degradable: false` | 西地那非 | ⚠️ 这是**竞争性抑制的全部秘密** —— 占座但不可降解。改成 true，西地那非就完全失效了 |
| `TICK_MS` | engine.js | `100`（10 Hz）。**所有 tick 计数的语义基准**：`hold` / `timeout` / `pulse.period` / 药物 `ticks` 全是以 tick 为单位，改它等于全局重算 |
| `drive` 计算式 | engine.js | `count/(count+K)` 与 `activation/100`。这是"用饱和曲线替代米氏方程"的核心 |
| `applyActivation` 的 `room = 1 − activation/100` | engine.js | 受体饱和，防止激活度无限堆叠 |
| `_resolveConsume` 的 `share = cap × count / total` | engine.js | 槽位竞争公式，竞争性抑制的涌现来源 |
| 双缓冲机制 | engine.js `tick()` | 读快照 / 写 next / 末尾提交。去掉它，反馈回路会出现"遍历顺序幽灵先手" |

## 六、⚠️ 已知坑（调参前务必知道）

### 坑 1：节点上的 `band` 是个死参数

引擎里**只有 `rx.band`（反应边上的 band）参与运算**（`engine.js:428-429`）。
而 `nodes[].band`（节点模板上的 band，如 sGC 的 `[0,85]`）**引擎从不读取**。

- 后果 A：sGC 的 `editable: ['band', ...]` 让玩家能在侧边栏拖这个滑块，但**拖了没有任何效果**。
- 后果 B：`tools/sweep.mjs` 一直在扫 `sgcBand` 这个维度，但它是空转的 —— **网格搜索白白浪费了 1/4 的维度**。

> 待办：要么让引擎读 `tpl.band` 作为反应的兜底频段，要么把 sGC 的 `band` 从 `editable` 里去掉、并把 sweep 的这一维替换成别的有效参数。

### 坑 2：GTP 能量封顶让"能量枯竭"死法难以触发

引擎现在按 `made = min(made, gtp/gtpCost)` 对产量做能量封顶（杜绝透支）。
副作用：GTP 会**渐近到低位而不再触 0**，而判定要求 `GTP ≤ 0.5` 连续 20 tick 才算枯竭 —— 于是这个死法几乎不会触发。

> 想让"能量枯竭"重新可用，应把判定阈值改成相对量（如 `GTP < 池容的 5%`），而不是要求归零。

### 坑 3：极限环震荡是特性，不是 bug

Ca 会在 40~99 之间大幅震荡，这是 `sGC→cGMP→PDE5` 负反馈加延迟的必然产物，也是关卡 hint 里写明要教的东西（"PDE5 苏醒，一切反弹回去"）。
**压平它 = 抹掉关卡最核心的戏剧性。**

但它直接限制了 `goal.hold` 的上限：震荡不停，就别指望 Ca 能连续几十秒压在阈值以下。

## 七、调参工作流

```
改 A 档        → 直接玩，无需验证
改 B 档        → 自检配套约束 → node tools/build.js && node tools/smoke.mjs
改 C 档        → node tools/balance.mjs   （5 个场景，看结局对不对）
                 node tools/sweep.mjs     （网格搜索，找满足全部契约的参数）
改 D 档        → 停下，重新设计
```

### 验证的"契约"（`tools/sweep.mjs` 里的 CONTRACT）

调参的目标不是"看起来差不多"，而是这五条同时成立（至少 2/3 随机种子满足）：

| 场景 | 操作 | 期望结局 |
|---|---|---|
| 1 · 不干预 | — | `timeout`，且最低 Ca > 54（卡在负反馈死局） |
| 2 · 西地那非 @25s | 投 1 次 | `homeostasis`，且 < 70 秒通关 |
| 3 · 硝酸甘油 ×3 | @10s/18s/26s | `starvation`（能量枯竭） |
| 4 · 西地 + 硝甘 | 联用 | `toxicity`（cGMP 红区，对应临床绝对禁忌） |
| 5 · ODQ | 沉默 sGC | `timeout`，且最低 Ca > 54（通路熄火） |

### 改完自检清单

- [ ] 改动落在哪一档？C 档请务必跑 `balance` / `sweep`
- [ ] 改了 `timeout`，就检查它 ≤ `balance.mjs` 的 `maxTicks`
- [ ] 改了 `goal.hold` 的秒数，就同步改 `brief` 文案里写的秒数
- [ ] 动 GTP 相关（`pools` / `poolsRegen` / `gtpCost` / `amplify`），先看 idle 场景的 GTP 是否持平
- [ ] 五个场景的结局是否仍满足上表的契约
- [ ] 最后 `node tools/build.js && node tools/smoke.mjs` 全绿
