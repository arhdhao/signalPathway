# 构建脚本改造备忘

> 2026-09-05 · 对应代码：`tools/build.js`
> 面向：未来要往 `src/` 加模块、或打算拆分文件的人

## 改了什么

`tools/build.js` 原来是「硬编码 5 个文件的顺序 + 正则删掉 import/export + 字符串拼接」。
现在是「自动解析 import 建依赖图 → 拓扑排序 → 每个模块包 IIFE → 收集导出到命名空间表」。

## 为什么必须改

旧方案把 **所有模块的顶层符号平铺在同一个作用域**，且没有 IIFE 包裹。
实测当时 35 个顶层符号共享作用域，其中 `main.js` 独占 13 个
（`ui` / `level` / `chart` / `acc` / `sim` / `renderer` / `frame` …全是极常见的名字）。
零冲突纯属运气 —— 任意新文件里写一个 `const ui = ...`，合并后就是
`SyntaxError: Identifier 'ui' has already been declared`，且报错指不到是哪个文件。

对照实验（已验证）：两个新模块都定义 `const ui` / `const level`，
旧方案直接崩，新方案正常打包。

## 现在的行为

- **加文件不用改构建脚本**：自动扫描 `src/**/*.js`，从入口 `main.js` 出发做 DFS 拓扑排序。
  未被入口引用的文件会被跳过并提示，不会误打进产物。
- **构建期三类校验**：循环依赖（打印完整链路）、导入了不存在的导出（打印对方实际导出清单）、
  拼接后语法错误。全部在生成 dist 之前拦截。
- **作用域隔离**：模块各自包进 IIFE，顶层符号不再互相覆盖。

## 未来会踩的坑

1. **只支持 ESM 语法子集**：具名 / 默认 / 命名空间 / 别名 / 裸导入。
   动态 `import()`、`export ... from` 会触发「未处理的 export 语法」报错，
   需要同步扩展 `parseModule()`。
2. **打包后内部对象不再暴露到全局**（IIFE 的副作用）。
   浏览器控制台调试请用 `window.__sim`（在 `src/main.js` 末尾挂载）：
   `__sim.sim.metrics.Ca`、`__sim.sim.node('cGMP')`、`__sim.actions.applyDrug('ntg')`。
3. **`smoke.mjs` 依赖产物形态**：它用正则从 dist 的 `<script>` 里抠代码丢进 `vm` 跑。
   改打包结构后务必跑 `node tools/build.js && node tools/smoke.mjs`。

## 验证

改造前后产物行为**逐位一致**（固定随机种子跑 60 秒，Ca / cGMP / GTP / PKG / PDE5
等 14 个字段浮点数完全相同，结局同为「稳态恢复」），18 类 Canvas 绘制调用逐项一致。
`balance.mjs` / `sweep.mjs` 走 ESM 直连 `src/`，不受打包改造影响。
