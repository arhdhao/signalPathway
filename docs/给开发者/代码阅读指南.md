# 代码阅读指南

> 面向：有 Cocos / 微信小游戏经验、但第一次看这个项目的读者
> 目标：**两个小时内建立起整体图景**，而不是逐行读完 2589 行
> 更新时间：2026-09-05

---

## 一、先建立心智模型

你熟悉的 Cocos 和这个项目，三层是能对上的，只有两层对不上。

| 你在 Cocos 里熟悉的 | 本项目对应物 | 在哪个文件 |
|---|---|---|
| Model 数据层（血量、关卡状态） | `Simulator` + `Molecule` | `engine.js` |
| View 视图层（Sprite / Label） | `Renderer` + `Chart` | `render.js` |
| Controller 控制层（按钮回调） | `UI` + `actions` | `ui.js` + `main.js` |
| ⚠️ 场景树 / Prefab / cc.Node | **不存在，全部 Canvas 手绘** | `render.js` |
| ⚠️ `update(dt)` 单时钟 | **`frame()` 双时钟** | `main.js` |

**打叉的两行就是你看不懂的根源**，不是你水平问题 —— 这两处是 Web 原生开发的做法，Cocos 里根本不会出现。

### 差异一：没有节点树

Cocos 里拖一个 Sprite 进场景，它自动渲染、自动响应点击。
这里**什么都没有**：

- 没有 `cc.Node`，没有组件，没有父子关系
- 所有图形都是 `ctx.fillRect(...)` / `ctx.fillText(...)` 一笔一笔画出来的（`render.js` 的 `_drawNode`）
- 连"鼠标点到哪个分子"都是手写数学算的 —— 见 `render.js` 第 141 行的 `hitTest()`，
  它拿鼠标坐标去遍历所有节点做矩形碰撞检测

### 差异二：双时钟

Cocos 的 `update(dt)` 每帧调一次，逻辑和渲染绑在同一拍上。这里拆开了：

```
渲染：每 ~16ms 一次（60fps）  只负责画
逻辑：每 100ms 一次（10Hz）   只负责推演
```

`main.js` 的 `frame()` 用一个累加器把两条线对齐：每帧把「真实经过的毫秒 × 倍速」
攒进 `acc`，攒够 100ms 就跑一次 `sim.tick()`。

**为什么这么麻烦？** 两个好处：
1. 开 4 倍速时逻辑跑 4 倍，画面依然是流畅的 60fps
2. 固定步长 + 固定随机种子 = 结果可复现，这是配平脚本（`tools/balance.mjs`）能跑通的前提

## 二、阅读路线（别从头读到尾）

### 第 ① 站：`src/main.js`（123 行，约 20 分钟）

**目标**：看懂"程序是怎么启动的"。这是最短的文件，先建立全局感。

| 行号 | 看什么 |
|---|---|
| 27-31 | 创建 Model(`sim`)、View(`renderer`/`chart`) —— 相当于 Cocos 的场景初始化 |
| 36-62 | `actions` 对象 = 所有玩家动作的集合。UI 不直接碰引擎，全走这里中转 |
| 85-122 | `frame()` 函数 —— **相当于你的 `update(dt)`**，双时钟累加器就在这里 |

读完你应该能回答：暂停按钮按下去，代码走到哪里？
（答：`ui.js` 的 `btnPause.onclick` → `actions.togglePause()` → `sim.paused = !sim.paused`）

### 第 ② 站：`src/pathways/nocgmp/`（7 个文件，约 15 分钟）

**目标**：看懂"游戏世界长什么样"。**这站最重要，别跳过。**

这是**纯数据文件，零逻辑** —— 相当于你的关卡配置 JSON。整个游戏的世界观都在这儿。
它按「**变化的理由**」切成六层，而不是按分子切开 —— 想同一个分子从头看到尾反而更麻烦，
但好处是：改配色不可能影响平衡，改平衡也不可能让画面歪掉。

| 行号 | 层 | 内容 |
|---|---|---|
| 72-136 | ① VIEW | 画布尺寸 / 7 个节点的坐标 / 配色 / 连线样式。**改这里不影响模拟结果** |
| 139-205 | ② BIOLOGY | 7 个分子的档案 + 6 条反应关系。**这一层一个数字都没有** |
| 208-234 | ③ INTERACTION | 标签密码表 —— 决定谁有资格和谁碰撞 |
| 237-314 | ④ KINETICS | 半饱和 / 衰减 / 频段 / 放大 / 槽位。**改这里会直接改变手感** |
| 317-445 | ⑤ GAME | 关卡规则 / 宏观指标 / 4 种药物 / 玩家可调参数白名单 |
| 448-470 | ⑥ COPY | 简报 / 提示 / 结算小知识 |
| 473-513 | 组装车间 | 按 id 把六层查表合并，拼成引擎认识的 `NODES` / `REACTIONS` |

**判断口诀**（看到一个参数不知道放哪层，问自己一句）：

| 回答的是 | 放哪层 |
|---|---|
| 谁影响谁？ | ② BIOLOGY |
| 谁有资格和谁碰？ | ③ INTERACTION |
| 多强、多快、多容易？ | ④ KINETICS |
| 玩家怎么玩、怎样算赢？ | ⑤ GAME |
| 屏幕上长什么样？ | ① VIEW |

**关键认知**：`engine.js` 那 640 行只是个**解释器**，负责按规则推进这个世界。
先看懂数据，再看懂解释器，难度减半。

⚠️ 文件末尾的 `NODE_ORDER` / `REACTION_ORDER` **顺序有意义，别随手重排**：
反应顺序决定了每个 tick 消耗随机数的先后，顺序一变整局推演结果就变了。

想做第二关？复制这个文件改数据即可（引擎确实不用动 —— 但胜负判定目前还硬编码在引擎里，
见本文末尾「已知的坑」）。

### 第 ③ 站：`src/engine.js`（约 800 行，最慢，建议分两次）

⚠️ **绝对不要从上往下读**。按下面顺序跳读：

| 顺序 | 行号 | 是什么 | 为什么先看它 |
|---|---|---|---|
| 1 | 78-102 | `MoleculeTemplate` 分子模板 | 对应 nocgmp/ 里的一个 node，「出厂设定」 |
| 2 | 105-207 | `Molecule` 分子实例 | 运行时状态。重点看 137 行的 `drive` getter |
| 3 | 217-235 | `Reaction` 反应边 | 对应 nocgmp/ 里的一条 reaction |
| 4 | **337-400** | **`Simulator.tick()`** | **全项目的心脏，读通这个就通了** |
| 5 | 414-461 | `_resolveReaction()` | 四步结算：匹配标签→掷骰→挂 Buff→乘数增量 |
| 6 | 479-503 | `_resolveConsume()` | 槽位竞争 = 西地那非的原理（下面细讲） |
| 7 | 545-595 | `_judge()` | 四种结局的判定 |

**`tick()` 里的执行顺序**（337-400 行）：

```
快照状态到 next 缓冲
  → 阶段 0：NO 脉冲释放
  → 阶段 1-3：遍历所有反应边做四步结算
  → 提交 next → this（一次性切换）
  → 各自衰减
  → 资源池再生
  → 更新宏观指标（钙离子等）
  → 判定胜负
```

"双缓冲"听起来玄乎，其实就是：**这个 tick 内所有反应都读旧值、写新值，最后一起提交**。
目的是让信号传播严格延迟 1 tick，避免"谁先遍历谁占便宜"。

### 第 ④ 站：`src/render.js`（540 行，可以只看两个函数）

大部分是 Canvas 绘图命令，相当于 Cocos 引擎内部 —— 你平时不看引擎源码对吧？
这里也一样，**建议只看**：

- `hitTest()`（141-149 行）：手写的点击检测，看完就懂"没有节点树"意味着什么
- `draw()`（206-223 行）：每帧的绘制顺序（背景→连线→粒子→节点→内皮）

剩下的 `_drawNode` / `_drawEdge` / `_drawParticles` 全是绘图细节，用到再查。

### 第 ⑤ 站：`src/ui.js`（371 行，挑着看）

相当于 Cocos 的 UI 组件脚本。建议看：

- `_buildDock()`（136-159 行）：生成右侧四个药物按钮
- `update()`（166-207 行）：每 50ms 刷新一次仪表盘数字

## 三、三个必须搞懂的核心概念

### 1. `drive` —— 推动力（engine.js 第 137 行）

**全场最重要的一个公式**：

```js
drive = count / (count + K)     // 数量驱动的分子（如 cGMP）
drive = activation / 100        // 激活度驱动的酶（如 PKG）
```

含义：分子越多推动力越大，但**越接近上限越难继续涨**。
这就是"信号传导有天花板"的表达 —— 没有这个上限，任何放大器都会失控。

对应到生物直觉：这玩意儿就是**有效浓度**，或者是受体被占满的比例。

### 2. 四步结算（engine.js 第 414 行）

每条反应边，每个 tick 走一遍：

1. **匹配标签**：两个分子有共同 tag 才可能发生碰撞（三维结构密码）
2. **掷骰子**：0-100 的随机数落进 `[lo, lo + 宽度 × drive^hill]` 算命中
3. **挂 Buff**：命中就给目标加激活度，带倒计时
4. **乘数增量**：`produce` 类型的边批量产出下游分子（消耗 GTP）

本质是把微分方程降维成桌游规则。改参数时注意：**曲线陡峭度由 `hill` 控制，
不是 `power`** —— 改 power 会把 S 形曲线压成开关。

### 3. 槽位竞争（engine.js 第 573 行）—— 西地那非为什么管用

PDE5 的处理能力 = `slots × 激活度`，所有带 `PDE_Target` 标签的分子**按数量比例瓜分**。

西地那非的关键属性是 `degradable: false`：它**占座但不被清除**。
于是 PDE5 的算力全浪费在消化西地那非上，真正的 cGMP 反而被"保护"下来。

这个设计比"给酶挂沉默 debuff"真实得多 —— 机制是涌现的，不需要给每个抑制剂写特例。

## 四、边看边试：调试技巧

浏览器打开 `dist/信号通路模拟器.html`，按 F12 打开控制台，可以直接操纵运行中的模拟：

```js
__sim.sim.metrics.Ca                 // 当前钙离子浓度
__sim.sim.node('cGMP').count         // cGMP 分子数
__sim.sim.node('PKG').activation     // PKG 激活度
__sim.sim.pools.GTP                  // 剩余能量
__sim.actions.applyDrug('ntg')       // 手动投放硝酸甘油
__sim.sim.paused = true              // 暂停
```

（`window.__sim` 在 `main.js` 末尾挂载。因为打包后各模块被 IIFE 隔离，
内部对象不会自动暴露到全局，这是特意留的调试出口。）

**建议的玩法**：先观战 30 秒看负反馈怎么反弹，然后投西地那非看 cGMP 怎么涨上去。
对着代码看现象，比干读代码快得多。

## 六、改完之后怎么验证（三种场景，别混）

**① 开发时频繁调参 → 用 dev 服务器（推荐，不用打包）**

```bash
node tools/dev-server.mjs        # 启动本地服务器（默认端口 8123）
```

然后浏览器打开 `http://localhost:8123/src/dev.html`。
改 `src/` 下任意文件 → **保存 → 刷新浏览器** → 立即生效。
（服务器还在跑的话，这个标签页会一直是"活"的，改完就刷。）

**② 想快速看参数数值/结局是否合理 → 配平脚本（直接读 src，免打包）**

```bash
node tools/balance.mjs           # 5 个标准场景的结局与关键指标表格
node tools/sweep.mjs             # 网格搜索 / 多随机种子敏感性分析
```

比打开网页快得多，适合"这参数到底行不行"的判断。

**③ 发布给别人 / 双击运行 → 打包 + 冒烟**

```bash
node tools/build.js      # 重新打包成单文件 dist/信号通路模拟器.html
                         #（file:// 下 ES module 会被 CORS 拦，必须打包才能双击跑）
node tools/smoke.mjs     # 冒烟：在 Node 里用 DOM 桩跑 7200 帧，检查装配和渲染
```

**一句话工作流**：改参数 → 先 `balance.mjs` 看数值 → 数值 OK → 开发预览页刷新看画面
→ 全部满意 → `build.js` 出正式版。

**参数配平靠脚本扫，不靠手调** —— 一阶动力学的饱和特性很反直觉，手调必然踩坑。
另外提醒：网页（dist 或 dev）都只是"画面"，`balance.mjs` 给的是"判决" ——
同一参数下两者背后的逻辑引擎是同一份，不会打架。
