## 〇、一句话定位

**这不是一个定量动力学求解器，而是一台定性的拓扑推演机。**

它不解微分方程，也不做 Gillespie 精确随机模拟。核心手法是把连续动力学**降维成桌游规则**：
用「标签匹配 + 掷骰子 + Buff 倒计时」三件事，替代速率常数与积分器。

**设计取舍**：牺牲定量精度，换取三样东西——

1. **可解释性**：玩家能说清"为什么这一刻 cGMP 涨了"，而不是看着一条黑箱曲线
2. **可玩性**：随机性带来变数，参数可调带来策略空间
3. **可配平性**：固定步长 + 可复现随机数，让 `tools/balance.mjs` 能批量跑场景

**不要做的事**：不要把 `count` / `activation` 当成真实浓度去对标文献数据。它们都是无量纲的游戏刻度，只有相对大小和趋势有意义。

## 一、模拟机制总览

### 1.1 整体架构：三层单向数据流

```
关卡数据（数据层）        逻辑内核（计算层）          表现层（只读）
src/pathways/*.ts   ──▶   src/engine.ts        ──▶   src/render.js
  纯数据、零逻辑            Simulator 状态机            src/ui.js
  六层分层组织              不依赖任何 DOM              Canvas 绘制 + 仪表盘
```

**单向依赖是硬约束**：表现层读引擎状态，但绝不反向写入；引擎不认识任何具体分子名（`'NO'` / `'cGMP'` / `'GTP'` 这些字符串一个都不出现在引擎逻辑里）。

引擎是纯逻辑层，能在 Node 里直接跑——这正是配平脚本（`tools/balance.mjs`、`tools/sweep.mjs`）能脱离浏览器工作的基础。

### 1.2 关键模块职责

| 模块 | 位置 | 职责 |
|---|---|---|
| `TUNING` | `engine.ts:70` | 引擎级机制常量。改这里影响**所有**关卡 |
| `RNG` | `engine.ts:125` | mulberry32 伪随机源，可复现（默认种子 `20260904`） |
| `MoleculeTemplate` | `engine.ts:380` | 分子的「出厂设定」，静态元数据 |
| `Molecule` | `engine.ts:427` | 分子的运行时实例，持有可变状态 |
| `Reaction` | `engine.ts:558` | 一条反应边，携带 `effect` 类型与动力学参数 |
| `Simulator` | `engine.ts:596` | 大脑：主循环、药物投放、指标演化、胜负判定 |
| `LevelConfig` | `engine.ts:285` | **关卡数据契约**（接口），关卡文件必须满足它 |
| `LEVEL_NO_CGMP` | `pathways/nocgmp.ts:692` | 第一关的完整数据实例 |

### 1.3 时间步进：双时钟

| 时钟 | 频率 | 谁在跑 | 目的 |
|---|---|---|---|
| 渲染 | ~60 fps | `main.js` 的 `frame()` | 画面流畅 |
| 逻辑 | **10 Hz** | `sim.tick()` | 推演可复现 |

`TICK_MS = 100`、`TPS = 10`（`engine.ts:50-51`）。`main.js` 的 `frame()` 用累加器把两者对齐：

> 每帧把「真实帧间隔 × 倍速」攒进 `acc`，攒满 100ms 就跑一次 `sim.tick()`；`guard < 12` 防止一帧内补跑几百步卡死浏览器。倍速档位 `SPEEDS = [1, 2, 4]`。

**为什么必须固定步长**：帧率随设备变化，若逻辑跟着帧走，同一套参数在 60Hz 和 144Hz 屏幕上会推出不同的故事。固定步长 + 固定种子 = 结果可复现，这是配平脚本有意义的前提。

### 1.4 一个 tick 的完整流程

`Simulator.tick()`（`engine.ts:738`）是全场唯一的心跳。严格七步，**顺序不可调换**：

| # | 阶段 | 做什么 |
|---|---|---|
| 1 | 快照 | 把 `count` / `activation` 拷进 `nextCount` / `nextActivation`（双缓冲） |
| 2 | 外部脉冲 | `pulse` 配置驱动的信号源喷发（本关是内皮细胞释放 NO） |
| 3 | 四步结算 | 遍历 `reactions`，**读 `this.*` 快照、写 `next.*` 缓冲** |
| 4 | 提交 | `next → this` 一次性原子切换 |
| 5 | 自身衰减 | 每个 `Molecule.onTick()`：激活度衰减、Buff 倒计时、物质自然降解 |
| 6 | 资源再生 | `poolsRegen` 补充 GTP 等资源池 |
| 7 | 指标与判定 | `_updateMetrics()` → `_judge()` → `_snapshot()` |

**双缓冲为什么必须存在**：所有反应在同一 tick 内读同一份旧快照、写各自的缓冲区，末尾统一提交。这样无论 `reactions` 数组怎么排序、通路里有没有反馈环，信号传播都是**严格 1 tick 延迟**，不会出现"谁先被遍历谁占便宜"的幽灵先手。反馈密集的通路（本关的 PDE5 负反馈）尤其依赖这一点。

## 二、走查：Demo 关卡「NO–cGMP」

关卡文件：`src/pathways/nocgmp.ts`，关卡 id `no-cgmp`。
生物学原型：KEGG map04022（cGMP-PKG 通路）+ 西地那非竞争性抑制 PDE5 的临床经典案例。

### 2.1 分子节点

| id | 名称 | role | 驱动方式 | 关键参数（`④ KINETICS`） |
|---|---|---|---|---|
| `NO` | 一氧化氮 | messenger | `count` | `K: 30`，`baseDecay: 0.115`（半衰期极短） |
| `sGC` | 可溶性鸟苷酸环化酶 | amplifier | `activation` | `decay: 0.015`，`buffTicks: 18` |
| `cGMP` | 环磷酸鸟苷 | messenger | `count` | `K: 62`，`baseDecay: 0.022` |
| `PKG` | cGMP 依赖性蛋白激酶 | kinase | `activation` | `decay: 0.05`，`buffTicks: 20` |
| `MLCP` | 靶蛋白 / 钙调控复合体 | effector | `activation` | `decay: 0.085`（衰减最快，PKG 一哑火立刻反弹） |
| `PDE5` | 5 型磷酸二酯酶 | decoy | `activation` | `decay: 0.03`，`buffTicks: 26` |
| `Sildenafil` | 西地那非 | decoy（**`kind: 'drug'`**） | `count` | `K: 200`，`degradable: false`，`metabolism: 0.006` |

### 2.2 反应边与标签密码

`② BIOLOGY` 定义六条反应，`③ INTERACTION` 定义谁能和谁碰：

| 边 | 拓扑 | effect | 关键动力学参数 |
|---|---|---|---|
| `r1` | NO → sGC | `activate` | `band: [0,58]`，`hill: 1.4`，`power: 22` |
| `r2` | sGC → cGMP | `produce` | `band: [0,72]`，`amplify: 14`，`gtpCost: 1.0`，`costPool: 'GTP'` |
| `r3` | cGMP → PKG | `activate` | `band: [0,62]`，`hill: 1.6`，`power: 42` |
| `r4` | PKG → MLCP | `activate` | `band: [0,78]`，`hill: 1`，`power: 48` |
| `r5` | PKG → PDE5 | `activate` | `band: [0,52]`，`hill: 1.4`，`power: 30` |
| `r6` | PDE5 → cGMP | `consume` | `slots: 7.5`，`slotTag: 'PDE_Target'` |

**标签（密码）表**——两个分子**共享至少一个标签**才可能碰撞：

| 标签 | 持有者 | 设计意图 |
|---|---|---|
| `NO_Signal` | NO、sGC | NO 与受体的对接密码 |
| `cGMP_like` | cGMP、PKG | 次级信使 → 激酶的结合口袋 |
| `PKG_dock` | PKG、MLCP、**PDE5** | ⚠️ 效应器与负反馈酶**共享** → PKG 一手救火一手点火 |
| `PDE_Target` | cGMP、**Sildenafil** | ⚠️ 底物与诱饵**共享** → 竞争性抑制的根源 |

**这两个"刻意共享"是整关的设计核心。** 想让 PDE5 不再误伤 cGMP，正确做法是去 `③ INTERACTION` 摘标签，而不是删掉 `r6` 那一行——删行等于宣告这个生物学关系不存在，摘标签只是让它碰不上，后者更符合机制本意。

### 2.3 外部驱动与资源约束

| 配置 | 值 | 含义 |
|---|---|---|
| `pulse` | `{ node:'NO', period:16, amount:30, cap:90 }` | 每 16 tick（1.6 秒）喷一发 NO，是全网唯一能量输入 |
| `pools` | `{ GTP: 1000 }` | 合成 cGMP 的「货币」，上限即初始值 |
| `poolsRegen` | `{ GTP: 3.0 }` | 每 tick 再生 3.0，基础合成 ≈ 再生使稳态可持续 |

### 2.4 一局推演的时间线

```
t = 0        Ca = 100（base 基准值），全网静默

t = 1.6s     第一发 NO 脉冲 → NO.count = 30
             NO.drive = 30 / (30 + 30) = 0.5
             r1 命中率 = 58 × 0.5^1.4 ≈ 22%  →  掷骰，命中则点亮 sGC

             sGC 激活 → r2 批量产出 cGMP（每个 GTP 换 14 个 cGMP 的产能上限）
             cGMP 累积 → drive = count/(count+62)，越积越猛但有天花板

             cGMP → r3 激活 PKG（hill 1.6，需要"数量淹没"才高效激活）
                     ↓
             PKG 双线出击：
               · r4 → MLCP 激活 → 抽走 Ca（主线，救火）
               · r5 → PDE5 激活 → 降解 cGMP（旁路，点火）

             Ca 演化：cur + (100 − cur) × 0.045 − MLCP激活度 × 3.2
                     ↑ 向基准回归        ↑ 被效应器抽走
```

**负反馈闭合**：PDE5 苏醒 → `r6` 按 `PDE_Target` 标签瓜分降解槽位 → cGMP 掉 → PKG 哑火 → MLCP 掉 → Ca 反弹。玩家什么都不做的话，会看到 cGMP 冲高、Ca 下降、然后一切弹回原点——关卡的 `hint` 文案就是引导玩家先观战看到这个振荡。

**玩家干预（西地那非）**：

```
投放 → Sildenafil.count += 620
     → 它带 PDE_Target 标签，能进 r6 的候选池
     → degradable: false  ← 关键开关
     → 按数量比例瓜分槽位时，它【占座但不被清除】
     → PDE5 的算力被大量浪费在"消化"西地那非上
     → 真正的 cGMP 被保护下来，浓度飙升
     → PKG 持续激活 → MLCP 持续工作 → Ca 被压住
```

**这不是特判规则，是涌现结果**：引擎里没有一行"西地那非抑制 PDE5"的代码，效果完全来自「共享标签 + 占座不退出 + 按数量瓜分」三条通用机制的组合。

### 2.5 关卡目标与胜负判定

判定逻辑在 `Simulator._judge()`（`engine.ts:993`），**引擎只提供四种「判定形状」，具体判谁、判多少、说什么话全部由关卡的 `OUTCOME` 表填写**（`nocgmp.ts:406`）。

| 结局 | reason | 判定条件 | 参数 |
|---|---|---|---|
| ① 稳态恢复（胜） | `homeostasis` | 核心指标 ≤ `below` 且**所有安全前置**满足，连续保持 `hold` tick | `metric:'Ca'`，`below:45`，`hold:50`（5 秒），`slipPerTick:2` |
| ② 能量枯竭 | `starvation` | 资源池 ≤ `emptyBelow` 持续 `sustainTicks` | `GTP`，`≤0.5`，`20` tick |
| ③ 脱靶毒性 | `toxicity` | 某分子越过红线持续 `sustainTicks` | `cGMP.count ≥ 190`，`40` tick |
| ④ 干预失效 | `timeout` | 跑满 ticks 仍未进入安全区 | `2000` tick（200 秒） |

两个容易忽略的设计细节：

- **`win.safe` 安全前置**：胜利不只看 Ca 达标，还要求 `cGMP < 190`（不在过量致死边缘）且 `GTP > 池容 10%`（代谢底物没烧穿）。这防止玩家"乱灌硝酸甘油把 Ca 短暂打下去"抢先判胜。
- **`slipPerTick: 2`**：进度条没达标时往回掉，且掉得比涨得快——抖动着蒙混过关是不行的。

结算文案用 `{占位符}` 模板（`⑥ COPY.outcomeText`），引擎的 `_finish()` 只负责把运行时数值填进去。`fillTemplate()` 找不到对应值时保留原样 `{name}`，方便一眼看出漏传了什么。

**四种可投放药物**（`⑤ GAME.drugs`）：

| 药物 | 快捷键 | effect 类型 | 机制 |
|---|---|---|---|
| 西地那非 | `1` | `spawn` | 投放 620 个不可降解诱饵，抢占降解槽位 |
| 硝酸甘油 | `2` | `boostPulse` | 90 tick 内 NO 脉冲幅度 ×2.0、周期 ×0.55；**有效期内重复投放会累加放大**（每次 `+boostStackBonus: 0.7`，即 2.0 → 2.7 → 3.4），这正是"叠加用药出事"的机制来源 |
| ODQ | `3` | `mute` | 沉默 sGC 70 tick，验证"上游被阻断下游会怎样" |
| 能量合剂 | `4` | `restore` | 补充 400 单位 GTP |

## 三、分子建模

### 3.1 静态元数据 vs 运行时状态

分子被刻意拆成两个类：

| 类 | 位置 | 内容 | 生命周期 |
|---|---|---|---|
| `MoleculeTemplate` | `engine.ts:380` | 标签、频段、放大倍数等「出厂设定」 | `reset()` 时从关卡数据构建 |
| `Molecule` | `engine.ts:427` | 当前数量、激活度、Buff 倒计时等 | 每 tick 被读写 |

`MoleculeTemplate` 的构造只有一行 `Object.assign(默认值表, 关卡配置)`——关卡里没写的字段自动拿默认值，写了的才覆盖。所以关卡文件可以写得很稀疏。

### 3.2 两套「量」：数量与激活度

这是分子建模最容易混淆的地方，**同一条信号链上两类分子交替使用不同的量**：

| 量 | 字段 | 用于 | 推动力公式（`Molecule.drive`，`engine.ts:474`） |
|---|---|---|---|
| 数量 `count` | `Molecule.count` | 信使分子、药物（NO / cGMP / 西地那非） | `count / (count + K)` |
| 激活度 `activation` | `Molecule.activation` | 酶、受体（sGC / PKG / MLCP / PDE5） | `activation / 100` |
| 脉冲 `pulse` | `Molecule.count` | 外部信号源 | `count > 1 ? 1 : count` |

**`drive`（推动力）是全引擎最重要的一个概念**，取值 0–1，相当于"有效浓度"或"受体被占满的比例"。

两种算法共用同一个设计意图：**越接近上限越难继续涨**——这就是「信号传导有天花板」的代码表达。没有这个饱和特性，任何放大器都会失控。

第三个分支 `pulse` 目前是为外部信号源保留的，本关未使用。

### 3.3 状态机

`Molecule.status` 只有三态：`Inactive` / `Active` / `Muted`。

| 状态字段 | 位置 | 行为 |
|---|---|---|
| `timer` | `Molecule.timer` | Buff 倒计时。期内激活度衰减放慢到 **×0.35**，过期后加速到 **×2.0**（「修饰被移除，迅速回落」） |
| `muteTimer` | `Molecule.muteTimer` | 沉默倒计时。期内每 tick 激活度 **×0.90** 崩塌，且 `drive` 强制归零 |
| `buffs[]` | `Molecule.buffs` | 带倒计时的状态标签数组，同 id 刷新取 max |
| `status` | 派生 | `activation ≥ 55`（`TUNING.activeThreshold`）且未沉默时显示 `Active` |

**激活增益不是直接相加**：`applyActivation()`（`engine.ts:494`）用 `room = 1 - activation/100` 做饱和趋近——越接近满值越难继续上升。注意它读的是 `this.activation`（本 tick 快照），写的是 `nextActivation`（缓冲），保证同一 tick 内多次激活不会自我叠加放大。

### 3.4 位置与呈现

`x` / `y` 是**设计稿逻辑坐标**（`① VIEW.layout`，画布 1000×400），渲染层按容器实际尺寸自动缩放。

**位置不参与任何模拟计算**——这是分层设计的直接收益：改坐标不可能影响模拟结果，改衰减率也不可能让画面歪掉。

### 3.5 抽象层级（给设计人员）

- **不追踪单个分子实体**。屏幕上流动的粒子是渲染层根据 `lastGain` 现生成的视觉效果（`render.js` 的 `_emit()`），后台只有 7 个聚合标量在更新。
- **`activation` 是 0–100 的抽象刻度**，不是浓度、不是磷酸化比例、不是任何有物理单位的量。它只保证单调性和可比性。
- **`count` 是浮点**，不是整数分子个数。

## 四、分子间交互关系建模

### 4.1 四种关系类型

`EffectKind`（`engine.ts:169`）定义了四种关系，覆盖激活、抑制、催化合成、酶促降解：

| effect | 语义 | 生物学对应 |
|---|---|---|
| `activate` | 掷骰命中 → 目标挂激活 Buff | 配体激活受体、激酶磷酸化靶蛋白 |
| `inhibit` | 掷骰命中 → 目标挂沉默 Buff | 抑制剂阻断 |
| `produce` | 掷骰命中 → 批量产出下游分子 | 酶催化合成（sGC 把 GTP 转成 cGMP） |
| `consume` | 槽位竞争降解 | 酶促降解（PDE5 水解 cGMP） |

**关系建模的是"拓扑 + 强度 + 概率"，不是化学计量式**。没有配平的化学反应方程式，每条边只回答"谁作用于谁、多强、多容易发生"。

### 4.2 四步结算

`Simulator._resolveReaction()`（`engine.ts:816`）。每条边、每个 tick 走一遍：

| 步骤 | 做什么 | 关键公式 |
|---|---|---|
| ① 匹配标签 | `from.tags` 与 `to.tags` 有交集才继续（`produce` 例外） | — |
| ② 掷骰子 | 0–100 随机数落进区间算命中 | `chance = (band[1]-band[0]) × drive^hill` |
| ③ 挂 Buff | `activate` 加激活度（带倒计时）；`inhibit` 加沉默 | `delta = power × drive^hill` |
| ④ 乘数增量 | `produce` 批量产出并扣资源池 | `made = amplify × drive^hill × jitter × supply` |

**参数语义（调参必读）**：

| 参数 | 管什么 | ⚠️ 常见误解 |
|---|---|---|
| `hill` | **响应曲线的陡峭度 / 协同性** | 想改 S 形陡峭度改这里 |
| `power` | 命中后的力度幅度 | **改它只会把曲线压扁成开关**，协同性会丢 |
| `band` | 命中概率的基准区间 | `band[1] - band[0]` 才是有效宽度 |
| `K` | 半饱和常数（count 驱动） | 多少个分子能把 `drive` 推到 50% |
| `amplify` | 产能放大乘数 | 与 `gtpCost` 共同决定能量消耗速度 |
| `decay` | 激活度每 tick 衰减比例 | 与 `buffTicks` 共同决定"信号持续多久" |

**能量硬约束**：`produce` 的产量会被 `budget / gtpCost` 封顶，杜绝"池子只剩 2 点却白嫖 100 个产物"。所以能量枯竭表现为**产量平滑衰减**，而不是断崖式崩塌后凭空续命。

消耗哪个资源池由反应的 `costPool` 声明——引擎不认识 `GTP` 这个名字，第二关想让合成消耗 ATP，在关卡里写 `costPool: 'ATP'` 即可。

### 4.3 槽位竞争：竞争性抑制的涌现

`Simulator._resolveConsume()`（`engine.ts:885`）。这是全项目最精巧的一段机制：

```
酶的处理能力  cap = slots × (activation / 100)
                    ↓
所有带 slotTag 且 count > 0.01 的分子，按 count 比例瓜分 cap
                    ↓
degradable: false 的分子【占座但不被清除】
                    ↓
算力被浪费 → 真正的底物被保护下来
```

三条通用机制组合出了竞争性抑制，**没有为西地那非写任何特例**。相比之下，"给药后给酶挂沉默 debuff"是特判写法——每加一种抑制剂都要加一个分支，引擎会随关卡数量线性膨胀。

**槽位竞争同样遵守双缓冲**：读 `m.count` 快照、写 `m.nextCount` 缓冲。

### 4.4 参数配置与数据组织

关卡文件 `src/pathways/nocgmp.ts` 按「**变化的理由**」切成六层，而不是按分子切分：

| 层 | 内容 | 改动会影响 |
|---|---|---|
| ① `VIEW` | 画布尺寸、坐标、配色、连线样式 | 仅视觉 |
| ② `BIOLOGY` | 分子档案 + 反应拓扑。**这一层一个数字都没有** | 拓扑结构 |
| ③ `INTERACTION` | 标签密码表 | 谁能碰谁 |
| ④ `KINETICS` | 半饱和 / 衰减 / 频段 / 放大 / 槽位 | **模拟手感** |
| ⑤ `GAME` | 关卡规则、指标、药物、可调参数白名单、胜负配方 | 玩法与难度 |
| ⑥ `COPY` | 简报 / 提示 / 结算小知识 / 结局文案 | 仅文案 |

**定位口诀**——看到一个参数不知道放哪层，问自己一句：

| 它回答的是 | 放哪层 |
|---|---|
| 谁影响谁？ | ② BIOLOGY |
| 谁有资格和谁碰？ | ③ INTERACTION |
| 多强、多快、多容易？ | ④ KINETICS |
| 玩家怎么玩、怎样算赢？ | ⑤ GAME |
| 屏幕上长什么样？ | ① VIEW |

**层类型由引擎接口派生**（`nocgmp.ts:101-106`）：用 `Pick` / `Omit` 从 `MoleculeTemplateConfig` 和 `ReactionConfig` 切出每层的字段子集。这样每层字面量都受编译期校验——`role` / `effect` / `drive` 拼错会当场报 TS2820，不会等到运行时才炸。

**「组装车间」**（文件末尾）：`NODE_ORDER` / `REACTION_ORDER` 两个数组按 id 查表合并六层，摊平成引擎认识的 `NODES` / `REACTIONS`。它不含任何数据、不做任何计算。

> ⚠️ **两个 ORDER 数组的顺序有意义，不要随手重排**：绘制顺序（后者盖前者）和反应结算顺序都由它决定，而结算会消耗随机数——顺序一变，整局推演结果就变了，哪怕参数一个没改。

**引擎常量 vs 关卡数据的分界**（判断标准只有一条）：

> 换一个关卡，这个数字会不会跟着变？
> 　**会** → 它是关卡内容，放 `pathways/*.ts`
> 　**不会** → 它是引擎机制，留 `engine.ts` 的 `TUNING`

举例：「Buff 期内衰减放慢到 0.35 倍」是通用规则，在 `TUNING`；「cGMP 超过 190 判负」是第一关设计，在 `OUTCOME`。

### 4.5 数据如何驱动状态更新

完整链路：

```
nocgmp.ts 六层数据
    ↓ 组装车间摊平
LevelConfig（满足 engine.ts:285 的接口契约）
    ↓ Simulator.reset()
Molecule / Reaction 实例 + pools + metrics 初始化
    ↓ 每个 tick
遍历 reactions → 四步结算 → 写 next 缓冲
    ↓ 提交
衰减 / 再生 / 指标演化 / 判定
    ↓ 表现层只读
render.js 画粒子与节点 · ui.js 刷仪表盘 · chart 采样快照
```

**宏观指标**（不在网络中流动，是网络效应的"读数"）由关卡声明 `kind`，引擎只执行三种通式（`_updateMetrics()`，`engine.ts:934`）：

| kind | 公式 | 本关用例 |
|---|---|---|
| `driven` | `cur + (base - cur) × restore - 激活度 × drain` | 钙离子浓度（driver: MLCP） |
| `mirror` | 直接镜像某分子的 `count` | cGMP 浓度 |
| `derived` | `transform(另一指标)` | 舒张度 = 100 − Ca（本关未启用） |

**玩家可改哪些参数**由 `⑤ GAME.EDITABLE` 白名单决定（`setParam()`，`engine.ts:1086`）。这是「80% 参数写死、20% 开放」设计原则的落点——白名单保护的是"负反馈涌现"所必需的网络结构，玩家改不坏。

## 五、当前实现的边界与已知问题

新人看到下面这些**不用怀疑自己**，都是已记录的待办：

| 问题 | 位置 | 说明 |
|---|---|---|
| 节点级 `band` 不参与计算 | `nocgmp.ts:314` | 引擎只认反应级 `band`。sGC 的「命中频段」滑块目前无实际效果 |
| `_ntgBoost` / `_ntgFactor` / `_ntgPeriod` | `engine.ts:631-634` | 硝酸甘油状态硬编码在引擎里，违反「引擎不认识分子名」的自述原则 |
| `render.js` / `ui.js` 硬编码分子名 | `render.js:247/249`、`ui.js:224/239/364` | 分子名硬编码 6 处：`sim.node('NO')`、`level.redline.cGMP` ×2、`node('cGMP'/'PKG'/'PDE5')` ×3；另有硬编码数字 `m.count / 55` 与私有字段访问 `sim._pulseClock`。因此"换关卡不用动 UI"目前**尚未成立** |
| 多 `consume` 边指向同一底物会重复扣减 | `engine.ts:901` | 都按同一快照计算，可能为负。本关只有一条 `r6`，未暴露 |
| `produce` 无 room 上限 | `engine.ts:862` | 与 `applyActivation` 的饱和逻辑不一致，多 produce 边会超产 |
| 胜负阈值未配平完 | `engine.ts:990` 的 TODO 注释 | 看到"跑 200 秒还是 timeout"不必怀疑代码错了 |

### 演进方向（讨论中，尚未实现）

团队正在评估更换模拟内核，方向是把「概率调制的确定性增量」换成「固定通量的离散抽样」（τ-leaping 的二项近似），让竞争性抑制、米氏饱和、级联放大从碰撞统计中自然涌现。**本文档描述的是当前已实现的行为**，若内核更换，本文档需同步修订。

## 六、上手建议

1. **先玩再看代码**：浏览器打开 `dist/信号通路模拟器.html`，按提示先观战 30 秒看负反馈振荡，再投西地那非看 cGMP 涨上去。对着现象读代码，比干读快得多。
2. **调参用脚本，不用网页**：`node tools/balance.mjs` 跑 5 个标准场景，`node tools/sweep.mjs` 做网格搜索。一阶动力学的饱和特性很反直觉，手调必然踩坑。
3. **改代码走全回归**：`npm run check`（= tsc 类型检查+编译 → 打包 → 冒烟）。改参数前记得先 `npm run build:ts`，因为配平脚本吃的是 `build/` 产物。
4. **调试出口**：控制台可用 `window.__sim`，例如 `__sim.sim.metrics.Ca`、`__sim.sim.node('cGMP').count`、`__sim.actions.applyDrug('ntg')`。

详细的阅读路线与调试技巧见 [《代码阅读指南》](./代码阅读指南.md)。
