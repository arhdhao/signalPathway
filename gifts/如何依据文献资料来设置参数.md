# 一、首先纠正一个很关键的观念：真实世界不存在一个"NO发射量 = X"

例如你问：

> NO 的发射量是多少？发射频率是多少？

科研论文里可能出现：

- pmol/min/10⁶ cells
- pmol/min/mg protein
- nM/s
- nM
- molecules/cell/s
- 某种 NO donor 的浓度
- 某个时间窗口内的 NO fluorescence signal
- 某个组织中的 NO steady-state concentration

这些都不是同一个东西。

例如，早期对培养内皮细胞的直接测量发现，基础 NO 释放量大约可以是 **16.4 pmol/min/ml packed endothelial cells**；另一些研究报告 eNOS 产生量在不同刺激下大约 **5–200 pmol/min**。不同实验系统之间可以差很多。([PubMed][1])

更重要的是，NO 是高度扩散和快速反应的信号分子，所以：

**"产生了多少 NO"** 和 **"平滑肌细胞实际看到了多少 NO"** 不是一回事。

这是你以后建模必须掌握的第一原则。

# 二、所以你应该把参数分成 4 类

我建议你的游戏以后所有参数都按照这四层管理。

### 第一类：Production——产生速率

例如 $v_{NO}$，单位可能是 $\mathrm{mol/s}$ 或 $\mathrm{nM/s}$。

描述的是：

> eNOS 每秒产生多少 NO。

---

### 第二类：Concentration——局部浓度

例如 $[NO]$，单位是 $nM,\;\mu M$。

这才是 sGC 真正"看到"的东西。

现实研究对 NO 生理浓度的结果其实非常分散。

有综述认为，在真实生理信号范围内，NO 可能低到 **100 pM 或更低，到约 5 nM**；但另一些血管壁/血管周围测量报告了数百 nM，甚至 μM 级的值。这个巨大差异与测量方法、空间位置、血红蛋白清除以及自由 NO 与结合态 NO 的区别有关。([PubMed Central (PMC)][2])

所以你会发现一个很有意思的事情：

> **NO 根本没有一个可以随手填进代码里的"标准生理浓度"。**

这反而说明你的游戏不能简单照抄一个数字。

---

### 第三类：Enzyme kinetics——酶动力学

例如 sGC 的 $V_{max}$、$K_m$、$k_{cat}$、Hill coefficient。

这些描述：

> **这个酶本身有多快、多敏感。**

---

### 第四类：System parameters——整个系统参数

例如：

- sGC 总量
- PDE5 总量
- 细胞体积
- NO 清除速率
- GTP 可用量
- cGMP 基础浓度
- PDE5 激活程度

这些东西连接前面三类参数。

# 七、为什么不能直接把 1.26 μM/s 填进去？

因为论文的：

```text
1.26 μM/s
```

意思是：

> 在模型设定下，每秒 cGMP 浓度最多增加多少。

而你的游戏：

```js

```

意思大概是：

这两者并不在同一个坐标系。

而你的引擎：**10 TPS** 意味着：

$$1tick=0.1s$$

因此真实模型中的：

$$1.26\mu M/s$$

如果保持线性：

$$1.26\times0.1=0.126\mu M/tick$$

也就是：**每 Tick 增加 126 nM cGMP。**

这才开始进入可以转换的阶段。

# 八、然后你还需要解决"容量单位"

# 九、再看 PDE5，你会更容易理解

# 十、这个地方有一个非常重要的数学知识

真实的 PDE5 降解不是：

```text
每 Tick 固定 -50 cGMP
```

而更接近：

$$v=\frac{V_{max}[cGMP]}{K_m+[cGMP]}$$

这就是 Michaelis-Menten。

实际上那篇专门建立 NO/cGMP/VSMC 数学模型的论文就直接用了这个形式：

$$\frac{d[cGMP]}{dt}=V_{max,sGC}E_{5c}-\frac{[cGMP]V_{max,PDE}}{K_{m,PDE}+[cGMP]}$$

并取：

$$K_{m,PDE}=2.0\mu M$$

作为模型参数。([生理学期刊][4])

---

# 十一、这意味着你的 PDE5 游戏机制其实可以升级

你现在：

```js
actualDegrade =
    PDE5_Degrade * hitProbability;
```

是：

> **游戏化竞争模型**

很好玩。

但是以后你可以做第二代引擎：

```js
const v =
    Vmax *
    cGMP /
    (Km + cGMP);
```

然后：

```js
next.cGMP -= v * dt;
```

这样 PDE5 的"降解速度"就不是人工固定的。

它会自然产生：

```text
cGMP少
→ PDE5降解慢

cGMP多
→ PDE5降解加快

cGMP非常多
→ PDE5逐渐接近最大处理能力
```

这种**涌现行为**。

这非常适合你的游戏。

---

# 十二、而且你会发现一个非常漂亮的地方

你现在的"PDE5 有限槽位"，可以和 Michaelis-Menten 合并。

真实的 $K_m$ 其实就很像：

> **底物需要达到什么量级，酶的处理效率才明显起来。**

而 $V_{max}$ 就是：

> **这个酶系统最大能处理多快。**

所以游戏里可以把它们翻译成：

| 生物学参数                  | 游戏参数     |
| ---------------------- | -------- |
| Km                     | 饱和阈值     |
| Vmax                   | 最大处理能力   |
| kcat                   | 单个酶的处理速度 |
| [Enzyme]               | 酶数量      |
| [Substrate]            | Capacity |
| inhibition             | 处理效率下降   |
| competitive inhibition | 共享槽位竞争   |

这就形成了一套统一语言。

# 十五、实际上你现在的 `baseDecay=0.115` 可以进行反推

这个非常适合你。

你的 Tick 是：

$$dt=0.1s$$

如果：

```js
baseDecay = 0.115
```

假设它代表每 Tick 剩余：

$$1-0.115=0.885$$

那么连续近似的衰减常数：

$$k=-\frac{\ln(0.885)}{0.1}\approx1.22s^{-1}$$

于是半衰期：

$$t_{1/2}=\frac{\ln2}{k}\approx0.57s$$

也就是说：

> 你当前的 NO 游戏参数，大约隐含了 **0.57 秒半衰期**。

这个数量级其实并不离谱。

但需要注意，NO 半衰期高度依环境而变。在血液中，血红蛋白是极强的 NO sink，估计的反应速率可达 350–6500 s⁻¹，对应非常短的腔内半衰期；在组织不同区域又完全不是这么简单。([PubMed Central (PMC)][2])

所以你现在 `0.115` 这种参数，应该被视为：

**针对你的游戏空间和 Tick 系统校准出来的有效衰减参数。**

# 十六、反过来，你还可以从真实半衰期计算游戏参数

这个特别重要。

假设真实目标半衰期：

$$t_{1/2}=1s$$

而你的：

$$dt=0.1s$$

连续衰减：

$$C(t)=C_0e^{-kt}$$

其中：

$$k=\frac{\ln2}{t_{1/2}}$$

所以：

$$k=0.693s^{-1}$$

一个 Tick 后：

$$e^{-0.693\times0.1}=0.933$$

所以每 Tick 保留 93.3%。

那么你的游戏：

```js
decayRate ≈ 0.067
```

这样一个真实实验参数就被系统地转换成了游戏参数。
